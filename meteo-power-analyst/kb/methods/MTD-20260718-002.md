> ⚠ **2026-09-30 复核（本条目第 7/13 节的结论被推翻，务必先读本节）**
>
> 本文第 7、13 节原写"小时数据近乎实时、延迟仅约 12 分钟、可作为准实时观测源"，**该结论不成立**。
> 原因有三，均已匿名复现，详见新增的第 14–16 节与 `pitfalls/PIT-20260930-007`：
>
> 1. **落库延迟实测 8–21 h**（官方文档上限 24 h）。原"12 分钟"是把**模式预报行当成了观测行**。
> 2. **小时文件是"观测 + 预报"按变量拼接的**：`Hourly()` 默认 `model=True`，会带回**未来约 10 天**的
>    DWD MOSMIX 预报行，且与观测段数值无缝衔接、行内无任何标记。
> 3. **`wspd` 的单位在 2026-03-31 变过**：此前是 km/h，此后是报文原单位（中国站 m/s、美国站节）。
>    同一条时间序列跨 2026-03-30/31 会有一个约 3.6 倍的台阶。
>
> 原复核记录（第 6、8–12 节的批量下载与站点覆盖）仍然有效。

## 背景

地面观测数据是气象分析的基础，但直接从各国气象服务获取需要分别对接不同协议（NOAA ISD、DWD CDC、CMA 数据中心等），门槛高、格式混乱。Meteostat 作为聚合层，统一封装了全球气象站的历史观测数据，通过 Python 库提供 Pandas 友好的接口，免 API key，适合科研和教育场景。本条目基于 2026-07-18 的实际测试验证。

## 内容

### 推荐做法（recommend）

#### 1. 数据源概览

| 维度 | 说明 |
|------|------|
| 数据来源 | NOAA ISD / METAR、DWD CDC（`dwd_hourly`/`dwd_poi`）、**DWD MOSMIX 预报**（`dwd_mosmix`）等多源聚合 |
| 访问方式 | Python 库 `meteostat`（1.7.6 起实际读 `https://data.meteostat.net/`） |
| API key | 不需要 |
| 时间范围 | 历史数据（部分站点可追溯到 1900 年代） |
| 空间覆盖 | 全球气象站（密度不均，欧美密集） |
| 数据频率 | 小时、日、月、气候常态 |
| 授权 | 非商业免费，数据遵循各自原始协议 |

**⚠ 域名迁移（2026-09-30 实测）**：库 1.7.6 的 `interface/timeseries` 模块把端点覆盖为
`https://data.meteostat.net/`，小时数据实际取自 `data.meteostat.net/hourly/{年}/{站}.csv.gz`。
旧的 `https://bulk.meteostat.net/v2/hourly/…` 已停更（`v2/stations/*` 的 `Last-Modified` 停在
2026-03-30）。**直接拼 URL 的下游代码要改用 `data.meteostat.net`**；新的全站 Bulk 是
`data.meteostat.net/hourly/{年}.parquet`（beta，2026 年约 8.6×10⁸ B）。

**安装**：
```bash
pip install meteostat
```

#### 2. 核心接口

```python
from meteostat import Point, Daily, Hourly, Stations
from datetime import datetime

# 三种数据获取方式
# 方式 1: 按经纬度（自动找最近站）
point = Point(39.9042, 116.4074, alt=70)

# 方式 2: 按站点 ID
# station_id = "54511"  # 北京站

# 方式 3: 查询附近站点
stations = Stations()
stations = stations.nearby(39.9042, 116.4074, radius=50000)
```

#### 3. 日数据获取模板

```python
from meteostat import Point, Daily
from datetime import datetime

# 北京
beijing = Point(39.9042, 116.4074, 70)

# df 包含: tavg, tmin, tmax, prcp, snow, wdir, wspd, wpgt, pres, tsun
```

#### 5. 变量字段说明

**日数据字段**：

| `prcp` | 日降水量 | mm |
| `snow` | 积雪深度 | mm |
| `wdir` | 平均风向 | 度 |
| `wspd` | 平均风速 | km/h |
| `wpgt` | 最大阵风 | km/h |
| `pres` | 海平面气压 | hPa |
| `tsun` | 日照时长 | 分钟 |

**小时数据字段**：

| 字段 | 含义 | 单位 |
|------|------|------|
| `temp` | 气温 | °C |
| `dwpt` | 露点温度 | °C |
| `rhum` | 相对湿度 | % |
| `prcp` | 小时降水量 | mm |
| `wdir` | 风向 | 度 |
| `wspd` | 风速 | **⚠ 随时期变化，见第 15 节**（2026-03-30 及之前 = km/h；2026-03-31 起 = 报文原单位） |
| `pres` | 气压 | hPa |
| `coco` | 天气状况码 | 整数 |

**⚠ 单位不是列的属性，而是行的属性（2026-09-30 实测）**：用库读到的 `wspd` **没有单位标注**，

或直接读原始 CSV 的 `wspd_source` 列（库不暴露该列，见第 14 节）。日数据的 `wspd`/`wpgt`
未做同样的逐年复核，跨 2026-03-31 使用前建议按第 15 节方法自查。

| 码值 | 含义 |

| 1 | 晴 |
| 2 | 多云 |
| 3 | 阴 |
| 4 | 雾 |
| 7 | 小雨 |
| 8 | 中雨 |
| 9 | 大雨 |
| 14 | 小雪 |

#### 7. 数据完整性注意事项

- **缺失值**：用 `<NA>`（pandas NA）表示，不是 NaN，处理时需注意
- **站点密度**：中国地区站点稀疏，北京 50km 内仅 1 个站；欧美密集
- **数据延迟（2026-09-30 复核更正）**：**小时观测落库延迟实测 8–21 h**（官方文档上限 24 h），
  不是"近乎实时"。原"延迟约 10-15 分钟"的结论错误——那是把 `Hourly()` 默认带回的
  **DWD MOSMIX 预报行**当成了观测行。详见第 13、14 节。
- **版本与来源（2026-09-30 新增）**：同一行不同变量的来源可以不同（如温度来自 `metar`、
  降水来自 `dwd_mosmix`）。**中国站的小时 `prcp` 是 100% 的 DWD MOSMIX 模式值，不是雨量计观测**，
  详见第 16 节。涉及观测与模式分开比较的分析必须先判来源。
- **历史长度**：不同站点起始时间不同，需实际查询确认
- **单位**：温度默认 °C；**风速单位不可假定**，见第 5 节与第 15 节

#### 8. 大批量下载策略（2026-07-19 验证）

针对多站点、长时间范围的批量下载（如全国46个机场×2年），推荐以下策略：

**策略 1: 站点ID复用（关键优化）**

首次查询后保存 ICAO→station_id 映射，后续下载直接用 station_id 调用 `Daily(sid, ...)`，跳过 `Stations().nearby()` 查询，速度提升 3-5 倍。

```python
# 首次运行: 查询并保存映射
stations_metadata = []  # [{icao, station_id, station_name, ...}]

# 后续运行: 直接复用
for icao, sid in icao_to_sid.items():
    df = Daily(sid, start, end).fetch()
```

**策略 2: 逐级扩大半径搜索**

默认 30km 半径在中国西部地区常找不到站点。推荐逐级扩大：

```python
def find_station_with_expanding_radius(lat, lon):
    for radius_km in [30, 50, 100, 200, 500]:
        stations = Stations().nearby(lat, lon, radius=radius_km * 1000)
        df = stations.fetch()
        if len(df) > 0:
            return df.index[0], df.iloc[0]
    return None, None
```

**策略 3: 按ICAO号独立保存文件**

文件命名 `daily_{ICAO}.csv` / `hourly_{ICAO}.csv`，优势：
- 避免站点ID变更导致文件名混乱
- 按机场逻辑组织，便于业务使用
- 同一站点被多机场引用时（如北京首都/大兴共享54511），文件独立可追溯

**策略 4: 按年度分目录存储**

```
data/meteostat/
├── china_2025/     # 2025全年
│   ├── daily_ZBAA.csv
│   ├── hourly_ZBAA.csv
│   └── download_summary_2025.csv
└── china_2026/     # 2026年至今
    ├── daily_ZBAA.csv
    ├── hourly_ZBAA.csv
    └── download_summary.csv
```

#### 13. 数据实时性实测（2026-07-20 原始版 · 2026-09-30 推翻）

> **本节原结论已被推翻，保留原文以便对照。** 原文结论为"小时数据近乎实时，延迟仅约 12 分钟"，
> 依据是"测试时刻 2026-07-20 03:09 UTC，18 个站点的小时数据均更新到 03:00 UTC"。
> 该依据是**把模式预报行当成了观测行**——见第 14 节。**正确结论见第 13.1 节。**

**小时数据实时性**：**近乎实时，延迟仅约 12 分钟**

| 区域 | 测试站点数 | 最新小时数据 | 延迟 |

**日数据实时性**：延迟 0-2 天，存在地区差异（美洲当天、中国/越南/泰国次日、日本/韩国 2 天、

**关键发现**（原文）：
- 小时数据延迟远小于此前认知（原记"1-7 天延迟"实际仅适用于日数据）
- 与 NOAA ISD 原始数据（数月延迟）形成鲜明对比，Meteostat 聚合层接入了更实时的数据流
- 个别站点（如巴西 SBGR）日数据延迟可达 7 天，疑数据源更新频率问题
</details>

**为什么错**：2026-07-20 03:09 UTC 时"最新行 = 03:00 UTC"这件事本身是真的，但那一条 03:00 的行
是 DWD MOSMIX **预报**行。库默认 `end = 今天 + 10 天`、`model=True`，因此**返回结果的尾部永远是
预报**，索引看起来"更新到当前整点"是必然的，与观测是否入库无关。

| 悉尼 94767 | 2026-09-29 21:00 | **8.0 h** | 2026-10-09 22:00 | 234 |
| 河内 48820 | 2026-09-29 14:00 | **15.0 h** | 2026-10-09 15:00 | 227 |

- **结论**：小时观测落后 **8–21 h**，与官方文档"最多 24 h"一致。**不可用作准实时观测源**；
  近实时需求请用 METAR 原始报文、Open-Meteo 或卫星产品。
- 模式行的覆盖区间是"最后观测行 → 今天 + 10 天"，北京为 2026-09-29 16:00 ~ 2026-10-09 15:00，
  共 227 h ≈ 9.5 天，与库文档的 +10 天默认一致。
- 日数据延迟本节未重测，第 13 节原文的 0–2 天可继续参考。

#### 14. 观测与预报混在同一文件（核心陷阱）

**现象**：`data.meteostat.net/hourly/{年}/{站}.csv.gz` 是一份**按小时连续、无明显分段标记的合并序列**。
观测值随入库逐步写入；观测尚未到达的时段（最后观测行 → 今天 + 10 天）用 **DWD MOSMIX 预报值**填充，
数值与观测段无缝衔接。

**证据（北京 54511，2026-09-30 04:59 UTC）**：

| 检查 | 结果 |
|------|------|
| 文件总行 | 6,760（2026 年全年 + 未来） |
| `wspd_source == metar` | 6,380 行，末条 2026-09-29 15:00 |
| `wspd_source == dwd_mosmix` | 380 行，末条 2026-10-09 15:00，其中 **227 行在未来** |
| 两者时间戳重叠 | **0 个**（模式只填观测缺口，不覆盖已有观测） |
| `Hourly(…, model=True)` 默认 | 289 行，末条 **2026-09-30 04:00**，`wspd=18.5`（模式值，km/h 量级） |
| `Hourly(…, model=False)` | 276 行，末条 **2026-09-29 15:00**，`wspd=5.0`（观测值） |

**关键细节**：`Hourly(..., flags=True)` 只增加 11 个 `*_flag` 列（11 → 22 列），
**不暴露 `*_source` 列**。也就是说用库读数据时，**没有任何字段能告诉你哪一行是预报**。
要区分只能：① 传 `model=False` 只取观测；② 或绕开库直接读原始 CSV 的 `*_source` 列。

**做法**：
- 取观测做验证/真值对比：**一律写 `model=False`**，或自己按 URL 读 CSV 再过滤 `*_source`。
- 需要预报时段做连续性填充时才用默认 `model=True`，并**显式声明尾部是模式值**。
- 长序列拼接时注意：越靠后的日期被模式值填充的比例越大；随着观测入库，同一时次的行**会被改写**。

#### 15. 风速单位在 2026-03-31 发生切换

**现象**：`wspd` 一列在 2026-03-30 与 2026-03-31 之间存在约 3.6 倍的台阶，且**列名、来源标签都不变**。

**判据**：中国 METAR 一律以整米/秒报风（如 `03002MPS`）。若文件保留原值，`wspd` 就是 m/s
（春季最大值约 8–15）；若已换算成 km/h，则值落在 3.6 的整数倍上（4/7/11/14/18/22/25/29/32/36/40/43/47/50）。

**实测（与原始报文逐条比对）**：

| 时段 | 站 | 对照源 | 中位比值 | 结论 |
|------|----|--------|---------|------|
| 2026-02-10~02-20 | 54511 | IEM ASOS 原始 METAR | 3.50 | km/h（`36003MPS`→11.0、`VRB01MPS`→4.0） |
| 2026-03-10~03-20 | 54511 / 58367 / 59287 | IEM ASOS 原始 METAR | 3.60 | km/h（`10003MPS`→11.0、`01005MPS`→18.0） |
| 2026-05-10~05-20 | 54511 / 58367 | IEM ASOS 原始 METAR | **1.00** | **m/s**（`01002MPS`→2.0、`16005MPS`→5.0，0 条落在 3.6 档） |
| 2026-09-28~09-30 | 54511 / 58367 | aviationweather 原始 METAR | **1.00** | **m/s**（`VRB01MPS`→1.0、`08003MPS`→3.0） |
| 2026-09-28~09-30 | 72254（美国） | aviationweather 原始 METAR | ≈1.0 | **节**（`12008KT`→7.0，量级 0–8） |

**切换日期定位**（逐日看 `wspd` 最大值，中国三站一致）：2026-03-30 最大值仍为 18/32/47（km/h 量级），
**2026-03-31 起骤降到 5/6/8 且此后再无 ≥18 的值**。同一跳变在悉尼、开罗、河内等 METAR 站点同时出现，
说明是**上游整体改口径**，不是中国站个案。

**做法**：
- 跨 2026-03-31 使用 `wspd` 前，先按上面的"3.6 整数倍"判据确认所取时段的量纲。
- **不要**把 2026-03-30 前后的风速直接拼成一条序列。
- 库层面看不出单位，建议直接用原始 CSV 的 `wspd_source` 分组统计（各国站口径不同）。
- 该问题已向 Meteostat 反馈前需更多 MPS 站点复核；本条目按实测记录，不代替上游结论。

#### 16. 小时文件是"按变量拼接"的复合序列

**关键认识**：一行小时记录**不是来自单一数据源**。每个变量各自带一个 `<var>_source`，
同一行里 `temp` 可能来自 `metar`、`prcp` 来自 `dwd_mosmix`、`cldc` 来自 `metar`。

**各站逐变量的来源占比（2026 全年，实测）**：

| 站点 | `temp` | `prcp` | `wspd` | `cldc` | `coco` |
|------|--------|--------|--------|--------|--------|
| 北京 54511 | metar 94% | **dwd_mosmix 100%** | metar 94% | dwd_mosmix 85% | dwd_mosmix 94% |
| 上海 58367 | metar 94% | **dwd_mosmix 100%** | metar 94% | dwd_mosmix 55% | dwd_mosmix 96% |
| 广州 59287 | metar 94% | **dwd_mosmix 100%** | metar 94% | metar 66% | dwd_mosmix 96% |
| 河内 48820 | metar 94% | **dwd_mosmix 100%** | metar 94% | metar 68% | dwd_mosmix 85% |
| 奥斯汀 72254 | metar 93% | (空) 83% | metar 89% | dwd_mosmix 57% | dwd_mosmix 94% |
| 法兰克福 10637 | dwd_hourly 96% | dwd_hourly 96% | dwd_hourly 96% | dwd_hourly 96% | dwd_poi 59% |
| 悉尼 94767 | metar 94% | (空) 85% | metar 94% | metar 55% | dwd_mosmix 95% |

**要点**：
- **中国站的 `prcp` 全部是 DWD MOSMIX 模式值**，`coco`/`cldc` 也以模式值为主 ⇒
  中国站的 Meteostat 小时降水**不可当作雨量计观测**，只能作为"模式估的降水"使用。
- `wpgt`（阵风）大范围缺失（北京 95% 为空），沿用第"禁止做法"里的提示。
- 法兰克福一组以 `dwd_hourly` 为主，连降水都来自 DWD 观测；不同国家的来源结构差异很大。
- **所以**：任何"观测 vs 模式"的对比，必须在**变量级别**判来源，不能用"这一行是观测"这种说法。

### 禁止做法（avoid）

- ❌ 假设所有字段都有值（部分字段如 `wpgt`、`tsun` 常缺失）
- ❌ 用 `Point` 获取无人区数据（会返回最近站，可能距离很远）
- ❌ 不设置时间范围，全量拉取（数据量大，易超时）
- ❌ 混淆 `<NA>` 和 `NaN`，导致统计计算异常
- ❌ 用作风速、降水的业务决策（站点密度不足，精度有限）
- ❌ **用默认 `Hourly(...)` 拿"最新观测"**：默认 `model=True` 且 `end=今天+10天`，尾部一定是
  DWD MOSMIX 预报行，且行内没有任何标记。取观测必须 `model=False` 或按 `*_source` 过滤（第 14 节）
- ❌ **假定 `wspd` 是 km/h**：单位在 2026-03-31 由 km/h 改为报文原单位，中国站现在是 m/s（第 15 节）
- ❌ **说"这一行是观测"**：来源是按变量标注的，同一行里 `prcp` 可能是模式值（第 16 节）
- ❌ 把中国站的 Meteostat 小时 `prcp` 当作雨量计观测（2026 年该列 100% 来自 `dwd_mosmix`）

## 适用场景

- 历史气候分析（单站或多站时间序列）
- 科研项目的地面观测数据获取
- 气象教育与可视化
- 站点数据初步探查（找站点、查可用性）
- 验证模式输出与观测的对比

## 不适用场景

- **近实时/准实时业务**（小时观测落库延迟 8–21 h，文档上限 24 h；近实时请改用 METAR 原始报文、
  Open-Meteo 或卫星产品）
- **把小时降水当观测用**（中国站该列 100% 为模式值，见第 16 节）
- **跨 2026-03-31 直接拼接风速序列**（单位在此切换，见第 15 节）
- 高密度空间分析（站点稀疏，应使用再分析数据如 ERA5）
- 商业产品（需确认数据源授权）
- 中国区域精细分析（站点密度低，建议结合 CMA 数据）
