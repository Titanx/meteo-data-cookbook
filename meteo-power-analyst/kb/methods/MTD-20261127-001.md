# 派生/反演/AI 产品不是独立真值——用它验证另一产品前，先查共同输入链

> 结论一句话：凡"由模型、反演、迁移学习生成"的产品，都不能当独立观测真值去验证另一个产品；验证前先读它的训练数据/输入变量声明。两个产品高度一致时，第一假设是共同上游，不是互验通过。

## 结论

拿产品 A 验证产品 B 之前，必须列出两者的输入/训练链并找交集；有交集就只能降级为"交叉一致性检查"，结论写"一致"，不能写"验证通过、精度 X"。项目实测案例：GonshoreWT2024 与 GEM 电站库的 ERCOT 风电场 156/165（94.5%）距最近点位 <1 km，看似互验成功，实为两者都以 OSM 为起底点——一致性只证明同源（`recipes/RCP-20261127-001`）。

## 原理

派生产品的误差结构由其输入/训练数据决定，共享输入意味着共享偏差，比较时偏差互相抵消，"一致"不包含独立信息。六个独立案例（2026-11-23~27 调研）：

| 产品 | 共同输入问题 | 后果 |
|---|---|---|
| PARDIG-NRT | 输入含 ECMWF HRES 短报 | 不是纯卫星产品；与 HRES 比较会循环 |
| NSIDC-0813 | TLP-R2S 训练先验来自 ERA5，文件内自带 ERA5 对照列 | 拿 ERA5 验证即循环论证；且覆盖止于 2023-12-29 |
| GenFocal | 训练目标与评估参照同为 ERA5 | ERA5 上的"改善"不能当独立检验 |
| SAR 海面风 | GMF 反演 + 风向取模式背景场 | 风向信息来自模式，不是测量 |
| CMA 5G-A PWV | 论文用 ERA5 评估自家 PWV | RMS 3.3/4.2 mm 是对再分析，不是对真值 |
| GonshoreWT2024 | OSM 起底 + 遥感 ML 补漏 | 与同源点位库（GEM 坐标疑似同源）比较非独立验证 |

## 排查动作（可执行）

1. 读数据集页/论文的方法与数据声明节，找"训练数据 / 输入变量 / 先验 / 辅助对照"字样；
2. 列出候选参照产品的输入链，与被验产品求交集；
3. 有交集 → 结论降级为"交叉一致性"，并在文中写明共同输入是什么；
4. 真正的独立验证要找与双方输入链都不相交的真值源（探空、地基实测、人工影像判读）。

## 适用边界 / 什么时候不成立

- 共同输入 ≠ 没有价值：交叉一致性检查仍能发现某一方的管道错误（坐标错位、年份错配），只是结论不得冠以"验证精度"。
- 本条只处理"产品 vs 产品"；"产品 vs 现场实测"也有共同输入问题（再分析同化了站点数据），未系统整理，见待填充。

## 待填充（未验证部分）

- "一致率高到什么程度应触发同源怀疑"无定量阈值——GEM×GWT 的 94.5% 是事后归因，不是判据标定。
- 再分析与站点观测的"吸收性真值"问题（验证站点数据时应排除再分析同化影响）未整理。
