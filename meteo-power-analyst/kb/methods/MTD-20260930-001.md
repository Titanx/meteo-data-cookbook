# 数据与知识库约定：命名、单位、目录、凭据

> 最后更新: 2026-09-30（自旧知识库 conventions 目录迁入并按新架构重写）
> 成熟度: **verified**（跨 2026-07~09 全部轮次实际执行）
> 适用场景: 新增取数脚本、新增数据文件、新增知识条目、提交代码之前

## 结论

团队协作的摩擦大多不在算法，而在"同一个东西两种叫法"。
下列约定只要**在动手前花 10 秒核对**，就能省掉后面反复对齐口径的时间。

## 1. 数据文件命名

| 数据类型 | 命名模式 |
|----------|----------|
| 探空廓线 | `sounding_{站号}_{YYYYMMDD}{HH}Z.csv` |
| 地面站观测 | `{ICAO}_{YYYY}.csv`（按 ICAO 命名，避免站点变更导致管理混乱） |
| ERCOT 电价 | `ercot_{市场}_{枢纽}_{起始YYYYMM}_{结束YYYYMM}.csv` |
| SURFRAD 辐射 | `{站代码}{YY}.dat` |
| 雷达分块 | `{SID}_{Volume}_{ChunkID}` |
| Energy-Charts 年度整块 | `{国家代码}_public_power_{YYYY}.json` |
| ENTSO-E 月缓存 | `{内容}_{YYYY-MM}.csv` / `.xml` |
| NWP 逐 lead 归档 | `{国家代码}_nwp_prevruns_{起始日期}_{结束日期}.npz` |
| ERA5 实测归档 | `{国家代码}_ghi_archive.npz` |
| 汇成日面板 | `{国家或域}_{主题}_panel.csv` |
| 模型中间产物 | `{流程前缀}_{设定或指标}.csv` |

**分层纪律**：**原始响应按源原样落盘**（JSON / XML / npz / nc），
口径修正（变长块展开、合约过滤、重采样、时区归一）一律发生在派生层；
派生 CSV 只作消费层，可随时重算。

## 2. 脚本命名

| 类型 | 前缀 |
|------|------|
| 数据下载 | `download_{数据源}_{细节}.py` |
| 数据测试 | `test_{数据源}.py` |
| 数据检查 | `check_{内容}_{维度}.py` |
| 分析脚本 | `{主题}_analysis.py` |
| 管道流程 | `{数据源}_pipeline.py` |

脚本落位：进 `skills/<能力域>/references/`，不要散落在仓库根目录。

## 3. 知识条目

- ID 格式：`<PREFIX>-<YYYYMMDD>-<NNN>.md`，前缀 ∈ MTD（方法）/ DEC（决策）/ EXP（实验）/ PIT（坑）/ RCP（流程）
- 旧编号体系（GL- / PF- / PS-）已停用，对照见 `kb/MIGRATION.md`
- 成熟度三档：`draft`（单人经验）→ `verified`（≥1 次验证）→ `proven`（≥2 次验证）
- 新条目从 `kb/templates/` 拷模板 → 写完到分类 catalog 登记一行 → 跑闸门（见 §6）

## 4. 报告产物

每个报告一个目录，入口固定为 `index.html`，目录内自带字体与图表库，**零外部依赖**，
可独立打开或拷贝分发。骨架见 `kb/examples/report_outline_standard.md`。
`output/` 不纳入版本控制。

## 5. 单位约定

| 变量 | 单位 |
|------|------|
| 温度 | °C；气压 hPa；风速 m/s；风向 Degrees（0=北，顺时针） |
| 降水 | mm/hour 或 mm/day |
| 辐照度 | W/m²（GHI / DNI / DHI） |
| 电价（ERCOT） | $/MWh；电价（欧洲）€/MWh |
| 功率 | MW；能量 GWh / TWh |
| 份额 | 比值 ∈ [0, 1]（写"55%"与 0.55 等价，全文须一致） |
| CAPE / DCAPE | J/kg |

## 6. 凭据与提交闸门

- 凭据只进 `.env`（已被 `.gitignore` 排除）或系统环境变量，**禁止硬编码**；
  命名 `$env:{数据源大写}_API_KEY`，如 `$env:GRIDSTATUS_API_KEY`
- 不提交 data/、output/、.env、__pycache__ 目录；raw/ 层整层不进版本库
- 提交信息用 `{类型}: 简短描述`，类型 ∈ feat / fix / docs / refactor / data；
  流程类提交以**流程号开头**并把关键结论写进正文，便于日后按 ID 检索
- 改动知识库或任何 `SKILL.md` 后，提交前跑两道闸门：

```
python kb/kb_lint.py
python skills/kb-capture/references/secret_scan.py
```

## 局限

- 这些约定是**当前实践**，不是行业标准；换数据源或换市场时需要复议（尤其是命名模式）
- 单位约定只覆盖本项目已用到的变量，新增物理量必须补一行，否则口径很快会漂
