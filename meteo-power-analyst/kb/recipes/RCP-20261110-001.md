# Zenodo 超大 zip 数据包"免全量下载"读取管线（Range 流读 + zip64 解析 + HDF5 前缀切片）

> 成熟度: **verified**（2026-11-10 实跑：TGW/reV 三个 29–34GB zip 包免下载全包，成功解析 central directory 并切出 63 个完整 time 步的全域 CONUS 光伏/风电 CF 快照；物理自洽验证全部通过）
> 适用场景: Zenodo/HTTP 上单文件 10GB+ 的 zip 归档（内部是 NetCDF/HDF5 成员），只想看部分成员或部分时间步，不想拉全量。核心思想：**deflate 流不可随机访问，但"前缀"可以**——头部前几 MB 就够定位并读出数据集元数据与前若干时间步。

## 0. 结论速览

- Zenodo 大文件支持 HTTP Range（206），即使响应头缺 `Accept-Ranges`；**元数据 recid 与文件端点 recid 可能差一位**，下载 URL 必须用 `files[0].links.self`（用元数据 recid 拼 URL 会 404）。
- zip64 归档的 central directory 可从尾部 64KB Range 读出：EOCD64（`PK\x06\x06`）内 `+32/+40/+48` 依次是条目数/CD 大小/CD 偏移（**locator `PK\x06\x07` 里没有 CD 偏移**，别从那读）。
- **免下载全包读 HDF5 成员**：拉成员前 4MB raw（~5 分钟）→ zlib inflate 得 ~33MB 前缀 → 用 SparseFile 伪零填充绕过 h5py 的 stored_eof 截断校验 → 内存模式打开读全部元数据 → `ds.id.get_offset()` 拿数据绝对偏移 → 前缀内切片。
- TGW/reV 实测：33MB 前缀覆盖 **63 个完整 time 步**（2022-01-01 00:00 UTC 起 2.6 天全域 CONUS，299×424 格点）；对"看结构/抽首月样本"够用，**全年分析仍需全量**（见 §6 局限）。
- 单长连接下载会持续断流（Windows socket 层报误导性的 FileNotFoundError）；必须 4MB 分段 + 重试退避。zenodo.org 到国内链路实测仅 ~0.2MB/s，29GB 全包不可行。

## 1. 适用场景与前置输入

- 目标是 Zenodo 大记录（或任何支持 Range 的大 zip），想免下载全包地：① 摸清内部成员清单与结构；② 读取某成员的元数据 + 前若干时间步样本。
- 前置：`urllib`/`requests`（Range 请求）、`zlib`（raw deflate）、`h5py`+`numpy`、目标记录 recid 清单。
- 跳过条件：若数据源有官方子集 API 或门户代理（如 TGW 的 tgw-data.msdlive.org），优先走门户。

## 2. 步骤

### 2.1 记录清单与权威下载 URL

```python
meta = json.load(urllib.request.urlopen(f"https://zenodo.org/api/records/{recid}", timeout=60))
url = meta["files"][0]["links"]["self"]   # ★ 权威 URL, 别用 recid 手拼
```

- 母记录若只有 README（index record），从 description / related_identifiers 里正则捞子 DOI 清单再并发查元数据。
- HEAD 拿总大小并探测 Range 支持（206 即支持，`Accept-Ranges` 缺失不代表不支持）。

### 2.2 Range 流读 zip64 central directory

```python
tail = http_range(url, total - 65536, total - 1).read()       # 尾部 64KB
e64 = tail.rfind(b"PK\x06\x06")                               # EOCD64
n_total  = struct.unpack("<Q", tail[e64+32:e64+40])[0]
cd_size  = struct.unpack("<Q", tail[e64+40:e64+48])[0]
cd_off   = struct.unpack("<Q", tail[e64+48:e64+56])[0]
cd = http_range(url, cd_off, cd_off + cd_size - 1).read()     # CD 本体 (不在尾缓冲则再拉)
# 逐条目步进: 46B 定长头 + nlen+elen+clen; zip64 extra (hid==0x0001) 兜底 0xFFFFFFFF 字段
```

- 每条目拿到 `(name, method, csize, usize, lho)`；method=8 是 deflate。
- TGW 实测：单包 40+ 条目（`{情景目录}/{成员}_YYYY.nc` 命名），csize 737MB(solar)/1550MB(wind)。

### 2.3 成员前缀拉取（4MB 分段 + 退避重试）

- 从 `lho` 读 local header 30B，`nlen, elen = unpack("<HH", lh[26:30])`，`data_start = lho + 30 + nlen + elen`。
- 从 data_start 起按 4MB 段拉 raw（每段带 `2×(i+1)s` 退避重试 6 次），拼到 head_mb 截止。
- `zlib.decompressobj(-15)` 流式 inflate → 得成员文件的前 ~8.5MB 原始字节（4MB raw ≈ 33MB inflated，压缩比 ~8.3）。

### 2.4 SparseFile 绕过 h5py 截断校验 + 前缀切片

```python
class SparseFile:                # 前 len(real) 字节真实, 其余全零
    def __init__(self, real, total): self.real, self.total, self.pos = real, total, 0
    def read(self, n=-1):
        if n == -1: n = self.total - self.pos
        n = min(n, self.total - self.pos)
        if self.pos < len(self.real):
            data = self.real[self.pos:self.pos+n]
            if len(data) < n: data += b"\x00" * (n - len(data))
        else:
            data = b"\x00" * n
        self.pos += n; return data
    def seek(self, off, whence=0): self.pos = off + (0, self.pos, self.total)[whence]; return self.pos
    def tell(self): return self.pos
    def close(self): pass
    mode = "rb"

f  = h5py.File(SparseFile(head, usize), "r")   # ★ total 必须用该成员自己的 usize (zip 条目里就有)
ds = f["capacity_factor"]
off  = ds.id.get_offset()                       # 数据区绝对偏移 (TGW solar 2022: 1,098,442)
NT, NY, NX = ds.shape                           # (8760, 299, 424)
slab = NY * NX * 4                              # ★ 单 time 步字节数, 别写成全 dataset
n = (len(head) - off) // slab                   # 前缀内完整步数
cf = np.frombuffer(head[off:off+n*slab], dtype="<f4").reshape(n, NY, NX)
```

- h5py 拒开截断文件（`truncated file: eof != stored_eof`）**无法配置关闭**，SparseFile 伪零填充是干净的绕法：元数据层完全真实，数据区读零。
- TGW 的 `capacity_factor` 是 **contiguous 无 chunking**（float32，C-order），线性索引公式 `offset = data_off + t×slab + i×NX×4 + j×4`，因此前缀 = 时间维最前面的连续 n 步——对"取首段样本"恰好最理想。
- 坐标 `XLAT/XLONG` 是 2D WRF 投影网格（21.05–55.88°N / −133.77–−60.23°W），找最近格点用 `d2 = (lat-la)**2 + (lon-lo)**2` 全域 argmin，别假设规则经纬网。

### 2.5 物理自洽验证（每次切片后必做）

- [ ] 光伏：当地 solar midnight 前后全 0；正午 CF 峰值 0.6–0.9；峰值经度随 UTC 时间西移（t=12 峰在东部 ~−73°，t=18 峰在中部 ~−105°，实测命中）
- [ ] 风电：CF 量级 0.1–0.5 且**无日周期形态**（与光伏区分的关键）
- [ ] `Time[0]` 纳秒时间戳换算正确（TGW: 1640998800000000000 = 2022-01-01 00:00 UTC）
- [ ] 代表点 24h 曲线形状与已知气候一致（West TX 光伏 mean≈0.28、Boston 阴天 mean≈0.006）

## 4. 实测结果（TGW/reV，2026-11-10）

**管线实测**（zenodo→国内链路）：

| 目标 | recid | raw 拉取 | inflate 前缀 | 完整 time 步 | data_off |
|------|-------|---------|-------------|-------------|----------|
| solar 2022（历史） | 10138040 | ~190s | 33.1MB | 63 步 | 1,098,442 |
| wind 80m 2022（历史） | 10182848 | 1162s | 10.8MB | 18 步 | 1,169,198 |
| solar 2099（rcp85hotter） | 10140758 | 286s | ~33MB | 61 步 | 1,098,442 |

- 同变量不同年份 data_off **完全一致**（元数据布局逐年不变）→ 管线对任意年份成员通用；wind 与 solar 前缀大小差异 = 压缩率差异（wind 场噪声大，4MB raw 只解出 10.8MB）。
- 时间口径：步长 3600s；**solar 文件 Time[0] = 01:00 UTC（interval-ending），wind = 00:00 UTC（interval-beginning）**——做风光出力对齐时注意错一位。

**物理自洽验证（全部通过）**：光伏三站点日出/日落/正午 UTC 时刻与经纬度精确对应（WestTX 日出 t=14、MidCA 高原平台 0.73 持续正午 2h）；风电 WestTX 夜间爬升至额定平台、Boston 无日周期、海上点锋面过境型爬升（0→0.97 in 4h）；全域太阳峰值经度随 UTC 西移（t=18 峰在 ~−105°）。

**实体知识（reV 输出常数）**：
- wind CF **饱和值恒为 0.981**（reV 功率曲线 + ~1.9% 损耗），2022-01-01 冬季风暴时段 23% 格点同时饱和、Iowa 单点连续 18h 满功率——风暴日全域 mean 高达 0.51（非典型，全年 mean 应 ~0.3-0.45）
- solar CF **上限恒为 0.909**（~9% 系统损耗），日间格点 p95 ~0.85

**"气候信号"负结果（重要方法论教训）**：用 1/1/2022 vs 1/1/2099（rcp85hotter）单日对比：Boston 日能量 ΣCF 0.13→2.69（**+1920%**）、WestTX −40%、全域 mean −9%——**全部是天气尺度方差，不是气候信号**。2.6 天前缀样本的正确定位 = 管线验证 + 数据结构/物理自洽；任何气候变化结论必须全月/年代际样本（见 §6 后路）。**单日对比得出的"信号"必然是噪声，别写进任何结论。**

## 5. 性能坑与绕法

| 现象 | 原因 | 绕法 |
|------|------|------|
| 单长连接 217s 仅 36MB 后断流，socket 层报 FileNotFoundError | zenodo 边缘节点掐长连接；Windows 报错文本误导 | 4MB 分段 + 退避重试，短连接反而稳 |
| 4MB 分段 6 并发仍 ~0.2MB/s | 到国内链路本身限速 | 放弃全量思路，改走前缀切片（本 RCP 核心） |
| h5py `truncated file` 拒开 | stored_eof 校验硬编码在 HDF5 层 | SparseFile 伪零填充（§2.4） |
| 元数据 recid 拼下载 URL 404 | 元数据 recid 与文件端点 recid 差一位 | 一律 `files[0].links.self` |
| zip64 字段读到 0xFFFFFFFF | 4GB 上限字段截断 | extra field (hid=0x0001) 兜底解析 |

## 6. 局限与后路

- **只拿得到前 n 个 time 步**（前缀决定，TGW 实测 63 步 ≈ 2.6 天）：deflate 流式压缩，全年散布的时间步需要全量前缀。全年/复合事件分析的后路：① tgw-data.msdlive.org 门户代理；② 离线环境批量下载（境外带宽）；③ 联系作者要子集。
- `usize` 必须逐成员从 zip 条目取，不同年份/变量大小不同（solar ~4.4GB、wind ~4.9GB inflated），硬编码会在另一成员上错位。
- TGW 本身是 **reV 模型估计**（WRF 再分析驱动）非实测出力；情景名 rcp45/rcp85hotter|cooler 是 TGW 自定义组合，非 CMIP6 原生情景——引用时注意口径。
