# BSRN 地表辐照基准实测数据取数流程（PANGAEA 匿名通道）

> 最后更新: 2026-09-30
> 成熟度: **verified**（2026-09-30 在中国大陆办公网络全程无账号、无 cookie 实测：检索 / 覆盖矩阵 / 三个站的文件下载与解析 全部跑通）
> 功能: BSRN（Baseline Surface Radiation Network）是全球**基准级**地表辐照实测网络，号称"用现有最高精度仪器、最高时间分辨率（1–3 分钟）"测量。它不像 SURFRAD 那样给一个可遍历的目录，而是把每月数据拆成**独立数据集**经 PANGAEA 出版。本流程固化"检索 → 定位月度 DOI → 匿名取 textfile → 按文件头解析"这条链路。
> 结论一句话: **PANGAEA 通道匿名可取（实测），旧条目写的"需注册登录"是错的**；但列结构逐站不同、缺测用空字段、状态矩阵含非辐射记录，这三点必须先处理。

## 1. 定位：BSRN 与 SURFRAD 的分工

| | SURFRAD | BSRN |
|---|---|---|
| 覆盖 | 只有美国 | **全球**（含极地、赤道、海洋岛） |
| 数据组织 | NOAA 目录树，按天一个文件 | PANGAEA 数据集，**按月一个 DOI** |
| 取数 | 匿名 HTTPS 目录遍历 | 匿名 REST 检索 + DOI 内容协商 |
| 条目 | `[RCP-20260720-002]` | 本条目 |

两者都是**仪器实测**，是与卫星反演（NSRDB/PVGIS）、再分析（NASA POWER/ERA5）对照时的真值基准。
需要**美国境外**的实测基准时，BSRN 是首选（GEBA 是月均，ARM 需注册且以云/气溶胶为主）。

### 🔴 状态矩阵的"有数据" ≠ 有辐照数据

Barrow(BAR) 在矩阵里显示到 **2022**，实际该年入的是 **Radiosonde measurements（LR1100 探空）**；
它的**辐射**数据集（LR0100/LR0300）最新只到 **2019**。

原因：BSRN 把数据按"逻辑记录（LR）"分层——LR0100 基础辐射、LR0300 其他辐射、LR0500 紫外、
**LR1000 地面气象、LR1100 探空、LR1200 臭氧**、LR1300 扩展。站点交了探空不等于交了辐射。
⇒ **只要辐照，必须按辐射类 LR 或数据集标题（"…radiation at station X"）筛选，不能用矩阵的年份打勾。**

## 4. 取数流程

### 4.1 四步

1. **查覆盖**：打开覆盖矩阵，确认目标站、目标年份有数据（注意上面 LR 的坑）
2. **定位月度 DOI**：`advanced/search.php` 检索该站该年，得到 12 个 `YYYY-MM → DOI`
3. **取数**：`https://doi.pangaea.de/{DOI}?format=textfile`（匿名）
4. **解析**：跳过注释头，**按文件自带表头**建列（见 §5）

### 4.2 检索语法

```
https://www.pangaea.de/advanced/search.php
  ?q=project:label:BSRN +event:label:{站码} +citation:"radiation"
  &count=30
  &mindate={YYYY}-01-01&maxdate={YYYY}-12-31
```

返回 JSON，`results[].html` 里含标题与 `(YYYY-MM)`，`results[].URI` 是 DOI；
`totalCount` 可用于核查该站当年数据集条数。
站点合集也可用 `incollection:{ID}` 语法（例：Barrow 辐射合集 = `incollection:959215`）。

### 4.3 脚本

```
python skills/data-fetch-ground/references/bsrn_pangaea_pipeline.py --coverage
python skills/data-fetch-ground/references/bsrn_pangaea_pipeline.py --list TAT 2026
python skills/data-fetch-ground/references/bsrn_pangaea_pipeline.py --get QIQ 2026-06
```

`--get` 会下载到 data/bsrn/ 并按表头解析，打印记录数/列名/前 3 行。已实测跑通（见 §6）。

## 5. 数据格式（**逐站、逐年代都不同**）

文件是**文本 + 注释头**：头部以 `/* DATA DESCRIPTION` 开始，`*/` 结束；
紧接着一行是**表头**，其后是数据行；**列以制表符（tab）分隔**。

```
/* DATA DESCRIPTION:
Citation:   ...
Project(s): Baseline Surface Radiation Network (BSRN)
Coverage:   LATITUDE ... DATE/TIME START ... END ...
Event(s):   TAT (Tateno) ... BSRN station no: 16 ...
Parameter(s): DATE/TIME ... SWD [W/m**2] ... METHOD/DEVICE: Pyranometer, Kipp & Zonen, CMP21, SN 235381, WRMC No. 16046
License:    Baseline Surface Radiation Network License 1.0 (BSRN-1.0) (URI: ...)
*/
Date/Time	Height [m]	SWD [W/m**2]	...
2026-08-01T00:00	2	...
```

**实测列数**（同一天三站）：

| 数据集 | 列数 | 组成 |
|---|---|---|
| Barrow 2011-11 | **16** | 时间/高度 + SWD·DIR·DIF·LWD·SWU·LWU 各带 std + T2 + 气压 |
| Qiqihar 2026-06 | **21** | 时间/高度 + SWD·DIR·DIF·LWD 各带 std/**min/max** + T2·RH·气压（**无上行辐射**） |
| Tateno 2026-08 | **29** | 时间/高度 + SWD·DIR·DIF·LWD·SWU·LWU 各带 std/min/max + T2·RH·气压 |

⇒ **绝对不能硬编码列名**（SURFRAD 的 48 列固定格局在这里不成立）。
必须 `读到 */ 后取下一行为表头`，再把数据行按 tab 对齐到该表头。
同一站在不同年代也可能变列（列名与仪器更换都写在注释头 `Parameter(s)` 里，
含 **WRMC No.** 与仪器序列号，机理解释可比对用）。

**缺测**：**空字段**（相邻两个 tab 之间为空），不是 SURFRAD 的 `-9999.9`。
⇒ `pd.to_numeric(errors="coerce")` 会把空字段变成 NaN，这是正确行为；
但若误按 SURFRAD 习惯去判 "< −1000 为缺测"，**一个缺测都抓不到**。

**时区**：全部为 **UTC**（条款页明确 "all data (PANGAEA and ftp) are provided in UTC"）。

### 🔴 原生时间步长也逐站逐年代不同（1 / 3 / 5 分钟）

**BSRN 不是"全是 1 分钟数据"**。全历史 590 个站年里，**91 个的原生步长不是 60 秒**：
81 个站年为 **3 分钟**、6 个为 **5 分钟**（早期 SURFRAD 系 BON/BOS/DRA/FPE/GCR/SXF/BAR/SPO 的
1990 年代；NYA 1993–1999 的 5 分钟段）。同一站跨年代也会变（如 BON 1995 是 3 分钟、2025 是 1 分钟）。

⇒ **用"每天 1440 行"当分母算完整度会严重错**：全历史会被算成 **89.47%**，
凭空多出 10 个百分点的"缺测"；按各自原生步长算才是真实值 **99.32%**。

判别方法：读文件第 1、2 行数据的时间戳求差（`1995-01-01T00:00` → `00:03` = 180 秒）。
**任何重采样 / 缺测统计之前必须先做这一步**；每文件理论行数 = 当月天数 × (86400 ÷ 原生步长)。

**质检**：PANGAEA 归档**只做了格式检查，未加详细质控标志**；
官方原话 "detailed quality checks … have not yet been applied to the data"，
WRMC **强烈建议用户自行做质检**（配套 BSRN-Toolbox）。
⇒ 与 SURFRAD 每列自带 QC 码（0/1/2/3）**完全不同**：BSRN 的 textfile **没有 QC 列**，
"好数据"这个假设不能默认成立。

## 9. 适用 / 不适用

**适用**
- 美国境外（尤其亚洲、欧洲、极地、赤道）的辐照实测基准
- 卫星产品与再分析在中国的**地面真值**（QIQ 是当前唯一在测的中国 BSRN 站）
- 长序列辐射气候学（1992 起，部分站超 30 年）
- 仪器级溯源（注释头带 WRMC No. 与序列号）

**不适用**
- **需要 QC 标志**：BSRN textfile 无质控列，要做质检得自跑 BSRN-Toolbox
- **需要当天/近实时**：月度发布，滞后 1–3 个月（近实时请用 SURFRAD / SOLRAD）
- **需要规则网格**：站点稀疏，全球分析要选网格化产品
- **需要商用转售**：BSRN-1.0 明确禁止转售，且转第三方需 WRMC 同意

### 全历史续跑（2026-10-01 → 2026-10-02，已完成）

`--plan` 全量口径：590 个完整站年 / 7080 个文件（实际 **19.9 GB**，此前按 3.5 MB/月的估算
偏高到 24.8 GB；真实均值约 **2.8 MB/月**）。

**慢速分批机制**（"慢慢下、持续一天"）：
`--max-files N` 单次配额——每次只取按 **中国 → 美国 → 欧洲 → 其他** 排序的前 N 个未下文件；
由于已下文件自动跳过，多次运行天然构成断点续跑。实测 2 并发下 **约 47 文件/分钟**，
全量裸跑约 2 小时即可下完，因此"持续一天"靠**调度限速**而非下载速度实现
（每小时 220 个 ≈ 215 个/小时，约 22 小时覆盖剩余 4904 个）。任务已于下满后删除。

**长跑健壮性**（2026-10-01 补）：检索阶段 `months_by_year()` 原本无重试，一次网络超时
（WinError 10060）会中断整轮规划（实测 TOR 站触发）；现已给 `fetch()` 加
429/5xx/超时指数退避重试（4 次），并让单站检索失败**跳过该站继续**而非整轮退出。

### 工程陷阱：PANGAEA 会限流

6 并发下载在 ~1400 个文件处触发 **HTTP 429 Too Many Requests** 并中断；
降到 **2 并发 + 每请求 0.5 s** 后 1668 个文件零失败跑完（约 20 文件/分钟）。
