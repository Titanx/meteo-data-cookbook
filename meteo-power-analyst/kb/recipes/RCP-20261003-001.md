# 站点降水"日界（报告时间）"对齐检验流程

> 最后更新: 2026-10-03
> 成熟度: **verified**（2026-10-03 USW00094728 / USW00023183 / USW00012839 三站实测，
> 复原偏移 +5 / +7 / +5 精确命中各站时区）
> 执行入口: `skills/data-fetch-ground`

## 适用场景

把**站点降水当"真值"**去核验格点产品 / 数值预报 / 再分析时，必须先回答一个问题：
**这里的"一天"是从几点到几点？**

- 站点雨量计：**当地日历日**
- 数值预报 / 再分析：**UTC 日历日**

不回答就比，测出来的是"两个窗口的重叠程度"，不是预报技巧
（代价见 `pitfalls/PIT-20261003-002`：ΔPCC 0.09~0.28）。
本流程用小时观测把日累积窗口在 UTC 上扫一遍，反推每站真实日界。

## 前置输入

- [ ] 站号（GHCN 11 位，如 `USW00094728`）——**GHCNd 与 GHCNh 两边都要有**
- [ ] 目标年份
- [ ] 网络可达：GHCNd 走 NCEI WAF，GHCNh 走 AWS 公开桶 `noaa-ghcnh-pds`（均匿名）

## 步骤

- [ ] 1. **选站：先做双重可用性检查**，不要按国家批量套
      （东亚实测两边同时可用的很少，见 `pitfalls/PIT-20261003-003`）。先列举候选：

      ```powershell
      python skills/data-fetch-ground/references/precip_window_verify.py --list KSM
      ```

- [ ] 2. **跑窗口扫描**（默认 ±12 h，逐小时）：

      ```powershell
      python skills/data-fetch-ground/references/precip_window_verify.py --station USW00094728 --year 2024
      ```

      脚本内部已固化 GHCNh 的正确聚合口径（floor 到小时 → 按小时取 max → 求和）
- [ ] 3. **自检一：量级还原比**应 ≈1.0（实测 1.04~1.06）。
      落在 0.01~0.05 或 >2，说明聚合口径错了，**此时任何相关结论都不成立**
- [ ] 4. **自检二：最优偏移是否等于该站标准 UTC 偏移的相反数**。
      命中 → 复原正确；系统性偏离 → 先查时区/夏令时，再查数据
- [ ] 5. **记录错位代价**：`PCC@0h` 与 `PCC@最优` 的落差（本项 0.09~0.28），
      作为"未对齐基线"随结论一起给出
- [ ] 6. **看峰位平台宽度，把日界当区间报**：PCC-偏移曲线在 1 小时步长下常是**宽平台**
      （本项迈阿密 +5~+8，宽 4 h）。**不要用分月 argmax 去论证季节机制**——
      本项实测每个月的峰位几乎都落在平台里（10/11、11/12、4/5 个月），
      且不施行夏令时的凤凰城也出现季节漂移，**"按月拆 DST"已被证伪**
      （见 `pitfalls/PIT-20261003-002` 第 4 节）
- [ ] 7. **把推断出的日界当元数据留存**，不要藏进预处理；对齐只改时间边界、不改量级，
      因此对齐后仍应保留独立的偏差/量级检验

## 产出

- 逐站结论（最优偏移 / PCC 落差 / 年度量还原比 / 峰位平台区间）：data/station_precip/precip_window_verify.json
- 逐站逐偏移的完整曲线（长表）：data/station_precip/precip_window_curves.csv
- 逐站逐月最优偏移与平台诊断（`reliable` 列）：data/station_precip/precip_window_monthly.csv
- 下载缓存：data/station_precip/_cache（复跑 0.5 s，无缓存约 30 s/站）

## 原理与坑

**原理**：站点上报的日值本身没问题，问题在于它的**窗口定义**与预报不一致。
小时观测的价值就在于窗口可以任意重切——所以"用小时值反推日界"是唯一不需要外部时区表、
也不依赖再分析的做法。相关峰的位置即真实的日界。

**必防的四个坑**：

1. **GHCNh 的 `precipitation` 是"自上次观测累积"，不是小时增量**——全加会虚高 ×2.45，
   必须按小时取 max 再求和
2. **GHCNh 时间戳不是整点**（`:51`/`:02`/`:22`）——按整点取数会几乎全空，
   指纹是"偏差比 0.0x + PCC 曲线阶梯状 + 最优偏移顶到扫描边界"
3. **GHCNd 与 GHCNh 站点集合不重合**——必须双重可用性检查
4. **不要用统一时区假设替代逐站推断**——报告时间由行政规定决定，同一国家成块、
   跨国/跨时区差异大，DST 还会造成季节性错配
