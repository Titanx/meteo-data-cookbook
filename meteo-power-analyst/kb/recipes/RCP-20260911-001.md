# GK2A (GEO-KOMPSAT-2A) AMI 卫星数据下载流程

> **类型**: process
> **成熟度**: verified
> **创建时间**: 2026-09-11
> **最后引用**: 2026-09-11
> **标签**: gk2a, geo-kompsat-2a, ami, satellite, s3, aws, korea, east-asia, china, geos, netcdf, satpy, himawari, fy-4, cross-validation
> **适用阶段**: architect, implement

## 背景

GK2A (GEO-KOMPSAT-2A) 是韩国气象厅的地球静止轨道气象卫星，定点 128.2°E，覆盖东亚区域 (含中国全境)。与日本 Himawari-9 (140°E) 和中国 FY-4 (104.5°E) 覆盖重叠，可作为交叉验证源或补充数据源。2026-09-11 验证了 AWS S3 匿名访问和 L1B 数据下载。

### 数据访问

- **S3 桶**: `noaa-gk2a-pds` (NOAA 托管)
- **认证**: 匿名访问，无需 API key
- **路径结构**: AMI/L1B/FD/{YYYYMM}/{DD}/{HH}/
- **文件命名**: `gk2a_ami_le1b_{channel}_fd020ge_{YYYYMMDDHHMM}.nc`
- **FD** = Full Disk, **020ge** = 2km GEOS 投影
- **每小文件数**: 16 通道 × 6 (10分钟间隔) = 96 文件/小时

### 下载方法

```python
import s3fs

fs = s3fs.S3FileSystem(anon=True)
# 列出文件
files = fs.ls("noaa-gk2a-pds/AMI/L1B/FD/202609/10/00/")
# 下载
fs.get(
    "noaa-gk2a-pds/AMI/L1B/FD/202609/10/00/gk2a_ami_le1b_ir105_fd020ge_202609100000.nc",
    "./gk2a_ami_le1b_ir105_fd020ge_202609100000.nc"
)
```

### 文件结构 (NetCDF-4)

```
dimensions:
    dim_image_y = 5500   # 行 (2km 红外)
    dim_image_x = 5500   # 列 (2km 红外)
    # 可见光 0.5km: 22000×22000

variables:
    image_pixel_values: uint16(5500, 5500)   # DN 值, 需定标

global attributes:
    satellite_name: "GK-2A"
    instrument_name: "AMI"
    channel_center_wavelength: 8.7           # μm
    channel_spatial_resolution: 2.0          # km
    projection_type: "GEOS"
    sub_longitude: 2.2375 rad (128.2°E)
    coff/loff: 2750.5/2750.5                 # 中心像素
    cfac/lfac: 20425338/-20425338            # 缩放因子
    nominal_satellite_height: 42164000 m
    earth_equatorial_radius: 6378137 m
    DN_to_Radiance_Gain: -0.0145              # DN -> Radiance
    DN_to_Radiance_Offset: 118.05
    Teff_to_Tbb_c0/c1/c2: ...                # Teff -> Tbb 修正
```

### GEOS → WGS84 投影转换

使用 satpy + pyresample 重采样到经纬度网格:

```python
from satpy import Scene
from pyresample import create_area_def
import dask
dask.config.set(num_workers=4)

scn = Scene(reader="ami_l1b", filenames=["gk2a_ami_le1b_ir105_fd020ge_202609100000.nc"])
scn.load(["IR105"])

area_def = create_area_def(
    "wgs84_grid",
    "+proj=longlat +datum=WGS84",
    resolution=0.02,              # ~2km
    area_extent=(73, 18, 135, 54)  # 中国范围
)
new_scn = scn.resample(area_def, resampler="nearest")
new_scn.save_datasets(filename="output_WGS84_China.nc", writer="cf")
```

安装 satpy 环境: `conda create -p D:\anaconda3\envs\satpy -c conda-forge python satpy`

### 验证结果 (2026-09-11)

- 匿名 S3 访问: 成功, 96 文件/小时
- IR105 文件: 33.6 MB/文件, 5500×5500 像素, 2km 分辨率
- WV073 文件: 27.9 MB/文件, 同 5500×5500
- 下载速度: ~8 MB/s, 8 文件 246 MB 用时 1 分钟
- 断点续传: 已实现, 跳过已存在文件
- GEOS 投影: sub_longitude=128.2°E, 需 satpy 重采样
- **实测延迟**（2026-09-29 全天 2,272 文件，用 S3 `LastModified` 反推，见 `[PIT-20260930-006]`）：
  - **标称时刻 → 落桶**：最短 21.3 / 中位 **23.2** / P95 38.7 / 最长 42.4 **分钟**
  - **扫描结束 → 落桶**：12.2 / 中位 **14.1** / 最长 33.3 分钟（全盘扫描本身 ≈9.1 分钟）
  - **双峰**：每小时 `:50` 时次稳定晚到 **41~42 分**，其余时次 21~27 分
  - 文件内属性可把链条拆开（实测）：`mission_reference_time=061000`（标称）→
    `scene_acquisition_time=061032`（采集）→ `file_generation_time=061953`（生成，+9.9 分）
    → S3 落桶（+23 分）
  - ⇒ **按"单个文件就绪"用，不要按"整个时次到齐"判断**
- 原记录的"06:36 UTC 时最新为 06:10 UTC，延迟 ~26 分钟"是**最新可用时次滞后**（另一种口径），
  与上表不冲突，但不能与 Himawari 的"~16 分钟"直接相减来比较速度

### 与其他静止卫星对比

| 卫星 | 国家 | 定点 | 通道 | 分辨率 | 标称→落桶（中位） | 扣扫描后 | 项目文档 |
|------|------|------|------|--------|------------------|---------|---------|
| **GK2A** | 韩国 | 128.2°E | 16 | 0.5/2km | **23.2 分** | 14.1 分 | PS-015 |
| Himawari-9 | 日本 | 140°E | 16 | 0.5/2km | **11.9 分** | 1.9 分 | PS-003 |
| GOES-19 | 美国 | 75.2°W | 16 | 0.5/2km | **10.2 分** | 0.1 分 | PS-004 |
| FY-4 | 中国 | 104.5°E | 14 | 0.5/2km | N/A (需认证) | — | PS-012 |

> 三者都是 10 分钟全盘；**口径统一到"标称→落桶"后，GK2A 仍最慢，但差距是 11 分钟而非"慢一倍"**，
> 且其中 9 分钟是 GK2A 自身扫描。原文"~26 分钟 vs ~16 分钟"用的是"最新可用时次滞后"，两者不可直接相减。

- GK2A 与 Himawari-9 的 AMI/AHI 传感器规格几乎相同 (同代设计)
- GK2A 定点位置 (128.2°E) 比 Himawari-9 (140°E) 更靠西，对中国西部观测角度更优
- 三星交叉验证 (GK2A + Himawari-9 + FY-4) 可提高中国区域卫星反演精度

### 注意事项

1. **可见光通道文件大且随昼夜变**: VI006 白天实测 **455 MB**、夜间 273 MB；IR/WV 稳定 18~36 MB。
   表里的"~200 MB"不能用于容量规划，见上文的体积说明
2. **GEOS 投影**: L1B 数据非经纬度网格, 必须用 satpy 重采样后才能与地面数据叠加
3. **satpy 环境**: 需单独创建 conda 环境, 不与项目主环境兼容
4. **S3 桶来源**: 数据托管在 NOAA (noaa-gk2a-pds), 非韩国 NMSC 直接提供
5. **数据延迟口径**: **标称→落桶 中位 23 分**（扣掉 9 分钟扫描后 12~14 分），每小时 `:50` 时次可到 41~42 分。
   NOAA S3 桶由 NOAA 中转上传, 非韩国 NMSC 直传。**建议按"单个文件就绪"使用（可作补充源），
   不要按"整时次到齐"判断**；如需更低延迟可尝试韩国 NMSC 官方渠道
