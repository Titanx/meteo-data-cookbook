# GonshoreWT2024 全球陆上风机点位下载、字段实检与 GEM 场站空间交叉核验——点位数据只够做坐标级核验，补不了装机清单

> 最后更新: 2026-11-27
> 成熟度: verified（2026-11-27 端到端跑通：Zenodo 下载 md5 核对 → 三处点数一致 → 重复坐标盘点 → 与本地 GEM ERCOT 清单 165 场站空间交叉）
> 结论一句话: **GonshoreWT2024（416,532 台陆上风机，ESSD 2026，Zenodo doi:10.5281/zenodo.18984175，CC BY 4.0）只有坐标 + `Nation` + `landtype` 三列，无容量/投运年/机型**——它能对 GEM 场站坐标做外部一致性核验（ERCOT 165 场站 94.5% 在 1 km 内），但不能替代 GEM 的容量清单，也不能补 GEM 2026 缺的约 4 GW；两套数据疑似共享 OSM 类上游，高一致率不是独立验证。

## 适用场景

- 需要**全球或区域风电点位**做坐标级核验、密度描述、土地利用静态分析时（执行入口：`skills/data-fetch-power/`）。
- 手上是 GEM 电站清单（场站级 + 容量），想验证坐标质量 → 本流程的空间交叉步骤。
- **不适用**：出力建模输入（无容量）、逐年新增分析（2024 截面）、把 landtype 占比当装机依据。

## 前置输入

- [ ] Python 3 纯标准库即可（本流程两个脚本不用 pandas/geopandas）
- [ ] 本地 GEM 电站清单 CSV（仓库根 data/gem/ercot_wind_plants_2026.csv，列 name/lat/lon/capacity_mw；生成见 `RCP-20260911-002`）
- [ ] 磁盘约 25 MB（zip 11 MB + 解压 231 MB，含 .dbf 207 MB）

## 步骤

- [ ] 1. **先查元数据再下载**：Zenodo API `https://zenodo.org/api/records/18984175` 核对 license（cc-by-4.0）、版本（v4）、文件清单与 md5。注意 recid 是**文件级** DOI（`10.5281/zenodo.18984175`），父版本 DOI 是另一个（conceptdoi 16759860），引用用文件级。
- [ ] 2. **下载并核对 md5**：直链 `zenodo.org/records/18984175/files/GonshoreWT2024.zip?download=1`。**实测必断流**（首轮 120 s 仅 1.5 MB；续传在 6.6 MB 处 `curl: (18)` 提前断），用 API `/content` 链接 + `curl -C - --retry-all-errors` 续传，完成后 `md5sum` 必须等于 API 返回的 `772618c25497af97f57dbf50be5f0bc8`。
- [ ] 3. **字段级实检（三处点数必须一致）**：
  ```powershell
  python skills/data-fetch-power/references/inspect_gonshorewt2024.py --base <解压目录>/GonshoreWT2024 --bbox -106.6 -93.5 25.5 36.5
  ```
  核对：`.shx` / `.shp` 实际点数 / `.dbf` 记录数三者相等（实测均 416,532）；字段仅 `OBJECTID`(N,10) / `Nation`(C,254) / `landtype`(C,254)；几何 PointZ 但 **Z 全 0、M 全 NoData**（无高程）；`.prj` 为 GCS_WGS_1984 经纬度。
- [ ] 4. **使用前按坐标去重**：实测 2,106 组完全同坐标（0.51%，按 1e-4° 约 11 m 为 2,532 行），最大组仅 2 条且属性相同（样例集中韩国，疑似 OSM 原始点与随机森林补漏点重叠）。场站级聚合前不去重会重复计数。
- [ ] 5. **与 GEM 空间交叉（可选）**：
  ```powershell
  python skills/data-fetch-power/references/crosscheck_gonshorewt_gem.py --base <解压目录>/GonshoreWT2024 --gem <仓库根>/data/gem/ercot_wind_plants_2026.csv
  ```
  输出最近距离分位数与阈值命中率；>5 km 的场站逐个人工复核（可能是坐标错、新场站或数据集漏检）。
- [ ] 6. **口径声明**：任何引用写明——点位数 ≠ 装机容量；`landtype` 是**点级**分类，论文里 45%/42% 是 **800 m buffer 面积口径**，两者不可混用；bbox 计数不是行政/电网边界。

## 产出

| 产物 | 内容 |
|---|---|
| 体检报告（stdout） | 三处点数、几何/Z/M、经纬度范围、重复坐标数、Nation/landtype 计数、bbox 点数 |
| 交叉核验报告（stdout） | GEM 场站最近 GWT 点距离中位/p90/max、各阈值命中率、离场站清单 |

## 实测结果（2026-11-27，ERCOT 区域）

- GEM ERCOT 风电 **165 座 / 37,928.2 MW**（与 `RCP-20260911-002` 的 38.0 GW 一致；2025 版文件与 2026 版内容相同）。
- 最近 GWT 点距离：**中位 0.02 km、p90 0.73 km、max 11.28 km**；≤0.3 km **77.0%**、≤1 km **94.5%**、≤2 km 97.0%、≤5 km **98.8%**。离群：Raymond wind farm 11.3 km、Lane City Wind 7.7 km。
- ⚠️ 高一致率**不等于独立验证**：GWT 以 OSM 起底，GEM 坐标疑似同源——只能说"两套清单高度一致"，不能说"GEM 坐标被独立证实"。
- 点级 landtype：Crops 172,243（41.4%）/ Rangeland 160,539（38.6%）/ Trees 12.9% / **Clouds 10,406（2.5%，云覆盖致分类未定，不是土地利用类）**；论文面积口径 45%/42%/87% 是 buffer 面积，不与点数混用。
- bbox (−106.6,−93.5)×(25.5,36.5) 内 25,691 点（US 24,879 + 墨西哥 812）——**含新墨西哥/俄克拉荷马狭地与墨西哥，不是 ERCOT 风机数**。

## 原理与坑

- **分类精度 ≠ 数据集完整率 ≠ 定位精度**：论文 ResNet-18 F1 98.3% / RF F1 99.4% 是验证样本上的分类表现，与"全球点位误差米级"之间没有推导关系。
- **同一论文内两处计数差**：416,532 − 375,197 = **41,335**（正文总数相减）vs 摘要 "updates **42,955** more"，差 1,620 台，口径未裁定，引用时注明出处。
- **PointZ 不代表有高程**：Z 列全 0、M 列是 NoData 哨兵值（−1.7977e308），需要海拔必须另找 DEM。
- **WGS84 经纬度做距离/buffer 前必须投影**；`Nation`/`landtype` 是 C254 宽字段带填充空格，读表须 strip。
- 下载断流续传、边缘 IP 池等 Zenodo 通用坑见 `[PIT-20261002-001]`；本条新增的经验是 **API `/content` 端点比页面直链更容易续传成功**。
