# 注释行就是表头：Greenbyte 导出的 CSV 用 `# ` 开头做表头，且字段含逗号

> 最后更新: 2026-10-02
> 成熟度: **verified**（2026-10-02 实测 Kelmarsh 2016 年 SCADA 原始 CSV，6 台机 / 52,416 行）
> 适用场景: 解析 SCADA 平台导出的"注释 + 表头 + 数据"混合 CSV（Greenbyte / 各厂商 SCADA 导出同型）

## 1. 坑：把最后一个 `# ` 行当成注释跳过，或对表头用 `split(",")`

Greenbyte 导出的 `.csv` 结构是**多行 `#` 注释 + 一行"也是 `#` 开头的表头" + 数据行**：

```
# Kelmarsh SCADA data
# Exported 2025-...
# ,Turbine 1,Turbine 1,...
# Timestamp,Wind speed (m/s),Power (kW),...
2026-01-01 00:00:00,7.3,1234.5,...
```

**注意最后一行注释本身就是表头**（列名行也以 `#` 开头）。

**两个错法**：

| 错法 | 后果（实测） |
|---|---|
| 把**所有** `#` 行都当注释 → 跳过 | 表头丢失，第一行数据被当列名，列数从 299 变 298 且整体错位 |
| 对表头行用 `split(",")` | 因为表头字段**带引号且引号内含逗号**，列数被切成 **464**（正确应为 **299**） |

**根因**：表头里有类似 `"Grid Meter, Active Power (kW)"` 的字段，引号内的逗号在 `split` 下变成分隔符。

## 2. 正解：用真正的 CSV 解析器，且只跳过"表头之前"的注释

```python
import csv, io

with open(path, encoding="utf-8", errors="replace") as f:
    lines = f.read().splitlines()

# 表头 = 最后一行以 "# " 开头的行
hd = max(i for i, ln in enumerate(lines) if ln.startswith("# "))
header = next(csv.reader([lines[hd]]))          # csv.reader 处理引号内逗号
header[0] = header[0].lstrip("# ").strip()      # 去掉首列残留的 "# "
data = list(csv.reader(lines[hd + 1:]))
```

**自检**：`len(header)` 应等于每行数据 `len(row)`；对不上就是分隔符/引号处理错了。

## 3. 附带坑：列多 ≠ 有数据

按列统计非空率（`check_windfarm_integrity.py --scada` 实测；列数均为 299，含时间戳列）：

| 年包 | 行数 | 原生步长 | 近乎无缺 | 部分缺 | **整列全空** |
|---|---|---|---|---|---|
| 2016 | 52,416 | 600 s | 5 | 102 | **192（≈64%）** |
| 2017 | 52,560 | 600 s | 12 | 149 | **138（≈46%）** |

⇒ **不要用 `df.shape[1]` 代表"可用变量数"**：2016 年近三分之二的列是空的。
**同一个电场不同年份的列集合与可用列数都会变**（2016→2017 全空列由 192 降到 138），
跨年拼接前必须先按列名对齐，并记录被丢弃的列。

## 4. 落地纪律

1. 解析前先**打印前若干行**，确认表头在哪、是不是也带 `#`
2. 一律用 `csv.reader`（或 pandas `skiprows=` 精确定位），**不要 `split(",")`**
3. 解析后立刻断言 `len(header) == len(data[0])`
4. 用**逐列非空率**当变量清单，不要用列数
