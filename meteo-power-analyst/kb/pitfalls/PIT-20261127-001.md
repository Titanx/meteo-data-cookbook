# 版本升级"算法不变"≠字段不变：MOD10A1 V7 静默删除雪反照率层；退役版本数据不可再取

> 结论一句话：升级数据产品版本时只改 URL 和版本号，可能静默丢变量——脚本不报错、结果缺层；且官方宣布退役的版本退役后数据不可再取，依赖它而不落盘 = 永久失去复现能力。

## 坑的描述（带数字）

NSIDC MODIS 积雪产品 C7（2026-11-19 公告）写明"科学算法沿用 V6.1 reprocessing"，差异仅来自 L1B 定标、新版陆水掩膜、定位 LUT，格式改 HDF5——听起来是纯技术升级。但 `MOD10A1` 的 V7 参数列只剩 SNOW COVER，V6.1 的雪反照率层 ALBEDO 被删除（项目用产品目录参数列独立核出：V61 = "ALBEDO | SNOW COVER"，V7 = "SNOW COVER"）。同时：六个 8 日/月合成产品继续 V6.1（MOD10A2/MOD10C2/MOD10CM/MYD10A2/MYD10C2/MYD10CM），其余产品的 V6.1 将在未来数月退役，官方明说**退役后数据不可再取、文档保留**。项目 `data/` 不进版本库——退役前不把原始文件落本地，将来只有文档没有数据。

## 排查信号（下次怎么认出来）

- 升级公告强调"算法不变 / 仅重处理 / 仅更新输入"——恰恰是这类最容易踩：官方叙事聚焦算法，字段增删藏在产品目录里；
- 文件格式变了（本例 HDF4→HDF5）；
- 数据系列出现两版并存（V7 与 V61 目录同时列出）＝交替期，字段 diff 的窗口；
- 依赖某变量的流程突然 KeyError/缺列，但"没改过代码"——先查版本，再查代码。

## 绕行方案

- 升级时做**字段级 diff**：新旧版本各取一个文件，对比变量/层清单与 dtype，而不是只对比数值或只改下载地址；
- 跨版本拼接前做重叠期对照——"同系列"不保证数值可续（算法不变，输入定标一变数值就变）；
- 流程依赖即将退役的版本：退役公告发布即把原始文件落本地并登记来源（既有纪律：原始响应按源落盘，口径修正只在派生层）；
- 需要被删变量（如雪反照率）：赶在 V6.1 退役前取数归档，或改走替代产品（VIIRS 对应层）。

## 真实案例

2026-11-24 调研 NSIDC 三条更新（NSIDC-0813 V1 / MODIS C7 / Terra 停测）时发现。公众号与官方公告都只说"算法不变"；反照率层删除是项目拿 NSIDC 产品目录参数列逐行对比独立核出的——只读公告一定踩。同批公告还确认 Terra 2026-12-01 停止新观测（历史档案保留），是"退役 = 不可复现"的另一实例。
