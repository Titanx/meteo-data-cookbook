# 把 NASA POWER 的辐照来源当成 MERRA-2 再分析：三处"看起来能查来源"的地方全是失效的

> 最后更新: 2026-09-30
> 成熟度: **verified**（由下游任务反馈触发，已按 API 原样复现全部证据）
> 适用场景: 任何引用 NASA POWER 的数据说明、报告"数据源"章节、跨源精度对比

## 1. 坑的描述

上游西班牙流程的数据源表把 NASA POWER 写成"**MERRA-2 再分析**"，下游据此把**辐照**也归给了 MERRA-2。实际分工是：

| 量 | 真实来源 |
|---|---|
| 辐照 GHI/DNI/DHI | **CERES**（正式版 SYN1deg；最近几个月是近实时 FLASHFlux） |
| 温度/风/湿度/气压 | MERRA-2，**最近时段已换成 GEOS-IT** |

即 MERRA-2 只是**气象要素**的来源，与辐照无关。把气象来源写成辐照来源，会让下游的质量判断、交叉校验与精度归因全部失准（例如据此认为"辐照精度低于 NSRDB 是因为 MERRA-2 粗分辨率"）。

## 2. 为什么一定会踩：三处"能查来源"的入口都失效

1. **CSV 响应头的参数描述是静态编目文本，不随实际来源变化。**
   实测：daily 2026-08-15 的真实 `sources` 是 `FLASHFLUX`，CSV 头仍写
   `ALLSKY_SFC_SW_DWN  CERES SYN1deg All Sky Surface Shortwave Downward Irradiance`；
   hourly 2026-09-20 气象源实际已是 GEOS-IT，CSV 头仍写
   `T2M  MERRA-2 Temperature at 2 Meters`。**CSV 头永远说 SYN1deg 与 MERRA-2。**
2. **参数元数据接口查不到真实来源。**
   - 单参数端点 `/api/system/manager/parameters/{参数}` **根本没有 `source` 字段**；
   - 批量端点 `/api/system/manager/parameters?...&metadata=true` 有，但 RE/HOURLY 的 105 个参数里
     **83 个返回字面占位值 `"SOURCE"`**，其余 22 个返回 `"POWER"`（意为 POWER 自行派生），
     **从不返回** SYN1DEG / MERRA2 / FLASHFLUX / GEOSIT。
   - `ALLSKY_SFC_SW_DWN` 正落在占位值那一组 ⇒ "查参数说明就知道来源"这条路是死的。
3. **唯一可靠读法是 JSON 响应的 `header.sources`。** 但它有两个反直觉之处：
   - 它是"本次请求**所有**参数来源的并集"，带 `POWER` 是因为请求里含派生参数
     （实测：只请求 GHI+T2M 得 `["SYN1DEG","MERRA2"]`；再追加派生指标 `ALLSKY_KT` 后变成
     `["MERRA2","SYN1DEG","POWER"]`）；
   - **数组顺序不稳定**——同一时段两次请求，MERRA2 可能在 SYN1DEG 之前，也可能在后，
     不能按顺序读成"主/次来源"。

## 3. 实测证据（2026-09-30，点位 lat 31.5 / lon −102.5）

| 请求 | `header.sources` |
|---|---|
| hourly 2025-07-01 | `["MERRA2", "SYN1DEG"]` |
| hourly 2026-09-20 | `["SYN1DEG", "GEOSIT"]` |
| daily 2026-05-15 / 06-15 | `["SYN1DEG", "MERRA2"]` |
| daily 2026-07-15 / 08-15 | `["FLASHFLUX", "MERRA2"]` |
| daily 2026-09-10 | `["FLASHFLUX", "GEOSIT"]` |

气象源从 MERRA2 → GEOSIT 的切换在 2026-07 与 2026-09 之间完成（hourly 2026-07-01 仍是 MERRA2）。

## 4. 排查信号

- 报告里出现"NASA POWER 是 MERRA-2 再分析"这类表述，且上下文在讲辐照 → 基本就是这个坑
- 想核对来源时，手边只有 CSV 或参数文档 → 拿不到真相
- `header.sources` 与文档/直觉不一致（例如拿到 `POWER`）→ 先怀疑"并集 + 顺序不稳定"，而非数据出错

## 5. 绕行方案

1. 取数时把 `header.sources` **落盘记录**（写进数据说明、npz/csv 的旁注或报告数据源表），
   不要事后凭印象回填
2. 写数据源表时分列声明：`辐照来源 = CERES(SYN1deg/FLASHFlux)`、`气象来源 = MERRA-2/GEOS-IT`，
   不要合并成一句"NASA POWER 是 XX 再分析"
3. 引用来源顺序无意义，一律当集合看
