# 同一 CSV 里堆叠了 81 个"累积快照"：行数虚增 41 倍，完整度会被算成 4138%

> 最后更新: 2026-10-03
> 成熟度: **verified**（2026-10-03 实测 Kelmarsh 2023/2024 年包，逐年解剖行/时间戳结构）
> 适用场景: 解析 SCADA 平台导出的"逐年一个文件"的 CSV；任何用"行数 ÷ 理论行数"评估完整度的地方

## 1. 坑：一个文件里塞了很多份"从头开始"的累积快照

Kelmarsh 2023 年包的 `Turbine_Data_Kelmarsh_1_2023-01-01_-_2024-01-01_228.csv`
（解压后 **2.9 GB**）实测：

| 指标 | 实测值 |
|---|---|
| 文件里的**数据行数** | **2,174,760** |
| 文件里的**不同时间戳数** | **52,560**（正是 365 天 × 144 的完整年） |
| 时间戳**回跳次数** | **80**（⇒ 共 **81 块**） |
| 首末时间戳 | 2023-01-01 00:00:00 → 2023-12-31 23:50:00 |
| 按"整文件行数 ÷ 52,560"算的完整度 | **4138%** |

**结构**：文件由 81 个块顺序拼接，**每一块都从 2023-01-01 00:00:00 重新开始**，
块长按 **655 行**递增：

| 块号 | 块长（行） | 累计到 |
|---|---|---|
| 1 | 655 | 655 |
| 2 | 1,310 | 1,965 |
| 3 | 1,965 | 3,930 |
| … | … | … |
| 81 | 52,560（截断到年末） | — |

算术自检：`655 × (1+2+…+80) + 52,560 = 655 × 3240 + 52,560 = 2,174,760` ✅

**成因（推断）**：导出器把**周期性生成的"年初至今"快照**逐个追加进同一个文件，
每次快照都从一开始重写整段历史。所以**只有最后一块是最完整的**（覆盖全年的 52,560 行）。

## 2. 排查信号（下次怎么认出来）

- **行数远超预期**：`实际行数 / (天数 × 每天条数)` 明显 > 1（本项是 41 倍）
- **完整度算出 > 100%**：任何"里程 >100%"都说明分子里混了重复数据
- **时间戳会往回跳**：按顺序扫一遍，只要有 `t < t_prev`，就存在多块
- **文件体积与行数量级不匹配**：一年一台机却 2.9 GB
- **不同时间戳数 ≪ 总行数**：本项 52,560 vs 2,174,760

## 3. 绕行方案

`时间戳回跳就清零重来`——流式扫一遍即可，O(1) 额外内存，天然只保留最后（最完整）那一块：

```python
prev = None
for row in reader:                 # 逐行流式
    t = row[0]
    if prev is not None and t < prev:      # 检测到新块 → 丢弃前面所有块
        n = 0
        nonnull = [0] * ncol
        first = None
    ...                                    # 正常累计 n / 逐列非空 / first / last
    prev = t
```

等价做法：按时间戳去重，**保留最后一次出现**的那条记录（后块覆盖前块）。

⚠️ 前提是多块**累积递增**（后面的块更长、更完整）。若块的语义相反（增量块），
则应保留第一块或按块合并——**先打印回跳处的首末时间戳，确认块语义再动手**。

## 4. 落地纪律

1. 拿到"一个文件覆盖一年"的导出，**先比一比 `行数` 与 `天数 × 每天条数`**，不要直接算完整度
2. 完整度一旦 >100%，先怀疑重复行，而不是先怀疑"数据超发"
3. 逐列非空率必须在**去重之后**统计，否则分母虚高、所有列的完整度都会被压低
4. 把"块数"作为体检输出的一项（本项脚本会打印 `块数 81`），便于一眼发现

## 真实案例

2026-10-03 核验 Kelmarsh 2023 年包：初次体检得到 `行数 2,174,760 / 列数 312 / 里程 4137.7%`，
与 2016–2022 的 52,416–52,704 行严重不符。解剖后确认是 81 个累积快照堆叠；
改为"回跳清零"后得到 **52,560 行 / 里程 100.0%**，与其余年份一致。

| 年份 | 整文件行数 | 去重后行数 | 块数 |
|---|---|---|---|
| 2016–2022 | 52,416–52,704 | 同左 | 1 |
| 2023 | 2,174,760 | 52,560 | **81** |
| 2024 | 2,174,904 | 52,704 | **81** |
