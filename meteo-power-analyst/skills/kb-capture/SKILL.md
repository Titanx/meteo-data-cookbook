# 知识沉淀与知识库维护

**状态**: 🟡 部分可用 — `kb/kb_lint.py`（七项检查）已验证可用；
"把本轮经验写成条目"是**人机协作流程**，尚无自动化脚本，靠本文件的规定执行。

**用途**: 把一轮研究里值得留下的东西**分层落位**，并保证知识库引用可达、索引不漂移。

**入口检查**:
1. 本轮结束时先问：这一轮产生的"结论 / 坑 / 决策 / 流程 / 样例"分别属于哪一层
2. 只写**能复用的**；一次性调试细节属于 raw/，不要污染 kb/
3. 写完必跑 `python kb/kb_lint.py`

## 分层落位（先判断，再写）

| 你手上的东西 | 去哪 | 判据 |
|--------------|------|------|
| 换个实现方式仍成立的原理 / 局限 | `kb/methods/`（MTD） | 有原理、有边界条件 |
| "为什么选 A 不选 B" | `kb/decisions/`（DEC） | 有前提、有被否决的方案、换前提会翻转 |
| "哪个更好"的对比数字 | `kb/experiments/`（EXP） | 有可复现配置；**与单一流程强绑定的留在 recipe 里** |
| 会踩的坑 + 排查信号 | `kb/pitfalls/`（PIT） | 能说出"看到什么现象就该怀疑它" |
| 端到端流程 | `kb/recipes/`（RCP） | 能写成可勾选的 checklist |
| 速查矩阵 / 报告骨架 / 字段样张 | `kb/examples/` | 是"形状"而非推导 |
| 本轮打印输出、试错、报错原文 | `raw/research-log/YYYY-MM-DD_<主题>.md` | **流水账**，允许粗糙、重复、矛盾 |
| 怎么调、什么参数、产出什么 | `skills/<name>/SKILL.md` + `references/*.py` | 跟着实现走 |

**分界线**：换个实现方式还成立的 → 知识层；跟着实现走的 → 能力层。

## 写一条新条目

```powershell
# 1. 从模板建条（ID 用当天日期 + 三位序号）
Copy-Item kb/templates/recipe.md kb/recipes/RCP-YYYYMMDD-001.md
# 2. 填正文；frontmatter 必须有 id（与文件名一致）和 maturity
# 3. 登记到分类 catalog（漏登记 = 静默失效，agent 永远找不到它）
# 4. 交叉引用用全 ID 加目录，如 recipes/RCP-YYYYMMDD-001
# 5. 检查
python kb/kb_lint.py
```

## maturity 怎么标（诚实优先）

| 级别 | 含义 |
|------|------|
| draft | 单次经验，未复现 |
| verified | ≥1 次实际验证 |
| proven | ≥2 次独立验证 |

衰减：draft 6 个月未引用归档；verified 9 个月降 draft；proven 12 个月降 verified。

## kb_lint 的七项检查

| # | 检查 | 不修的后果 |
|---|------|-----------|
| 1 | 失效知识 ID | 引用指向不存在的条目 |
| 2 | 失效链接 | 点进去 404 |
| 3 | 失效裸路径 | 反引号里的脚本/数据路径不存在 |
| 4 | **漏登记** | 条目在硬盘上但目录没收录 → **静默失效**（最主要的问题） |
| 5 | 孤儿条目 | 没有任何 skill 或条目引用它 → 等于没写 |
| 6 | 统计漂移 | 总目录声称的条数与实际不符 |
| 7 | 缺字段 | 缺 maturity 或 frontmatter id 与文件名不符 |

`--allow-orphans` 用于刚起步、还没有 skill 引用的阶段。

## 提交前两道闸门

改完知识库准备提交/推送时，**跑这两个检查，任一退出码非 0 就别提交**：

```powershell
# ① 引用可达性与索引一致性（漏登记是最危险的问题）
python kb/kb_lint.py

# ② 凭据闸门：防止 API key 随知识条目一起被推出去
python skills/kb-capture/references/secret_scan.py
```

`secret_scan.py` 做两道检查：① 若存在 `.env`，把其中的值当已知密钥在包内**逐值精确搜索**（零误报，主力检查）；
② 识别常见密钥形态（赋值型长值、URL 里的 token、`EA_`/`sk-`/`ghp_` 等前缀、JWT）。
它**刻意不**把裸的 64 位十六进制当密钥——会话摘要的 `summary_digest` 正是这种形态，会大量误报。

命中分级：位于 **git 已跟踪**文件 → 失败（推送会带出去）；位于未跟踪/被忽略文件 → 警告，加 `--strict` 才算失败。

**凭据落位纪律**：密钥只进 `.env`（已被 `.gitignore` 排除），脚本一律读环境变量，禁止硬编码。
`raw/` 层含会话记录与研究流水，**整层不进版本库**。

## 失败处理

- 改了条目数量或成熟度 → **必须同步 `kb/catalog.md` 的统计表**，否则第 6 项检查会报漂移
- 条目正文里写路径时，只写**本包内真实存在**的路径；运行期生成的数据与输出（`data/`、`output/` 下的具体文件）写成纯文本，不要加反引号
- 引用旧式 ID（如"见 PS-035"）→ 按 `kb/MIGRATION.md` 换算，不要留旧 ID
- raw/ 只增不改：写错了在文末追加"更正"段，不要回改历史
