# [PS-021] NSRDB 辐照批量提取与 pvlib 光伏出力建模验证流程

> **类型**: process
> **成熟度**: verified

> **最后引用**: 2026-09-27
> **标签**: nsrdb, pvlib, pvwatts, solar, ghi, dni, dhi, poa, single-axis, tracking, eia-930, ercot, validation, power-modeling, ilr, h5py, fsspec, chunked-extraction
> **适用阶段**: architect, implement, verify, analyze

## 背景

PS-019 完成了 NSRDB v3.2.2 的 S3 懒读取与 ERCOT 像素定位。本流程在其上打通全链路：
**GEM 电站坐标 → NSRDB 像素映射 → 分块批量提取 → pvlib PVWatts 出力 → EIA-930 实际出力验证**。
以 ERCOT 2022-07（56 座 ≥100MW 光伏电站，10.66 GW）为样例，实现小时级 r=0.9976、
月能量偏差 -2.1% 的物理建模精度，无需任何历史出力训练数据。

## 内容

### 1. 电站→像素映射（GEM × NSRDB）

- 输入：GEM 2026-08 整合版光伏库（PS-016）+ `nsrdb_v322_ercot_pixels.npz`（PS-019 产物）
- 筛选：operating 状态 + 2022 年前投运 + 装机 ≥10MW → 100 座匹配（中位距离 0.9 km）
- 建模子集：≥100MW 共 56 座（10.66 GW，占 EIA 全网口径 ~89%）
- 脚本：`scripts/data_download/match_nsrdb_ercot_solar.py`
- 产物：`data/nsrdb/ercot_solar_plants_pixels.csv`

### 2. 分块批量提取（h5py + fsspec，多进程自愈）

- **chunk 布局**：NSRDB 数据集 chunk 形状 2000(时间)×500(像素)；按时间块×列块切任务，
  每分量 245 块（5 时间块 × 49 列块），每块独立 npz 落盘
- **多进程**：ghi/dni/dhi 各 1 进程共享 1 个 h5py 句柄（B-tree 缓存命中后 ~1.7s/块；
  v1 教训：每块新开句柄需 ~20s B-tree 定位）
- **自愈重试**：每块 4 次重试 + 句柄重开（reopen 自身再 4 次重试，reopen 在 except
  块中抛出的异常不会被同一轮 for-try 捕获，必须独立 try）
- **断点续传**：以已存在 npz 文件为准（v2 教训：3 进程共写 progress.json 互相覆盖）
- **时间索引**：7 月行号 = 181×288=52128 起，31×288=8928 步（非闰年 7 月 1 日为年第 182 天）
- 脚本：`scripts/data_download/download_nsrdb_ercot_july2022.py`
- 产物：`data/nsrdb/ercot_solar_irradiance_2022-07.nc`（56 站 × 8928 × 3 分量，6.1 MB）

### 3. pvlib 出力链路（模型链）

```
GHI/DNI/DHI → solarposition → singleaxis(单轴跟踪) → POA
→ Tcell 参数化 → PVWatts DC → 逆变器 AC → 逐站求和 → 小时均值
```

标定参数（物理合理，非拟合过参）：

| 参数 | 值 | 依据 |
|------|-----|------|
| 跟踪 | N-S 单轴, max_angle 60°, **backtrack gcr=0.35** | 真实电站标配；无 backtracking 早晚低仰角 POA 高估 |
| ILR (DC:AC) | **1.25** | 2020 年代 ERCOT 新建主流 1.25~1.30 |
| 系统损耗 | **14%** | PVWatts 默认（soiling 2+wiring 2+mismatch 2+availability 3+其他） |
| 逆变器效率 | 96%，AC 裁剪至交流额定 | — |
| 温度 | Tcell = Tamb + POA/800×25, γ=-0.37%/°C | Tamb 25→39°C 日循环（2022-07 德州热浪） |

脚本：`scripts/analysis/nsrdb_pvlib_power.py`

### 4. EIA-930 验证结果（2022-07, 743 小时）

| 指标 | 值 |
|------|-----|
| 小时相关 r | **0.9976** |
| MAE | **185 MW**（EIA 峰值 9706 MW 的 1.9%） |
| 月能量 | 2871.2 vs 2931.7 GWh（**-2.1%**） |
| 昼夜曲线形状 r | 0.9993（正午偏差 ±150 MW / 1.7%） |
| 1h 爬坡相关 r | 0.9866 |
| 高出力段 (>6GW) MAE | 341 MW |

偏差分布：最差集中在 07-14~18 热浪核心期正午低估 10~20%（温度/气溶胶），
早晚肩部个别小时高估 30~66%（低仰角反演+跟踪器背光），对日能量影响 <0.5%。

### 5. 关键陷阱（本次实证，优先级最高）

1. **EIA-930 小时时间戳为区间结束（hour-ending）**：值属于 [t-1, t)。
   与气象/模型数据融合必须先 `-1h` 平移。实证：对齐前 r=0.942/MAE 785 MW，
   对齐后 r=0.992/MAE 346 MW（形状偏差集中在早晚肩部、最大偏差全部落在 13:00 UTC 是典型指纹）。
2. **pvlib 角度参数是度数不是弧度**：`singleaxis`/`get_total_irradiance` 误传弧度
   **不报错**——倾角恒为 0、AOI 全错、POA 退化为 DNI+DHI，且量级恰好接近真实值，
   极难察觉（本次靠"backtracking 改参无效"暴露）。修正后 r 0.992→0.998。
3. **pvlib>=0.10 `singleaxis` 返回 numpy 数组而非 Series**：`.fillna()` 不可用，
   需 `np.where(np.isnan(...))`。
4. **pandas Index 污染**：`DatetimeIndex.hour` 是 Index 不是 array，
   不 `.values` 会沿算术链传播导致 `Index does not support mutable operations`。
5. **fsspec/aiohttp 连接"病变"**：长进程读速可从 1 块/s 跌至 1 块/5min 而**不触发超时**
   （慢速涓流不断重置计时）；重启进程即恢复。网络本身正常（requests 实测 0.82 MB/s）。
   长批量任务应支持外部重启续跑，勿死等。
