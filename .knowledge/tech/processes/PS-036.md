# [PS-036] 西班牙 ENTSO-E Transparency 数据链路（替代 ESIOS）

> 最后更新: 2026-09-29
> 成熟度: **draft**（token 待申请；端点、协议、参数与解析器已实测验证）
> 功能: ESIOS 因 REE 域名级 WAF 封锁（[PF-013]）不可达后，改用 **ENTSO-E Transparency Platform** 获取西班牙的**分技术实际发电 / 实际负荷 / 日前电价**，用于校核与细化 PS-029~PS-035 的西班牙链路
> 结论一句话: ENTSO-E 的 REST API 在本机**端点可达、协议正常**（无 token 返回 `HTTP 401 + Acknowledgement_MarketDocument`，非 WAF 拦截页），只差一个免费 security token；拿到即可用，本地脚本已就绪

## 1. 背景与动机

西班牙链路（PS-029~PS-035）此前用 **Energy-Charts（Fraunhofer ISE）** 代理"实际分技术出力"，用 **OMIE** 拿日前价。二者都免注册、够用，但 ENTSO-E 是**欧洲输电运营商官方标准化口径**，可做三件事：

1. **口径校核**：把 Energy-Charts 的实际发电/负荷与 TSO 报送值对照，确认之前的结论不是数据源伪影。
2. **更细的时间分辨率**：ENTSO-E 按 TSO 报送粒度发布（解析器已支持 1/5/15/30/60 min），可用于日内结构分析。
3. **电价与出力同源对齐**：A44/A75/A65 均为同一平台、同一时区约定，避免跨源拼接的对齐风险。

## 2. 实测验证（2026-09-29）

| 项目 | 结果 |
|---|---|
| 端点 `https://web-api.tp.entsoe.eu/api` | **可达**；无 token 返回 **HTTP 401 + `text/xml`**，体内是标准 `Acknowledgement_MarketDocument`，`<text>Authentication failed.</text>` |
| 门户 `https://transparency.entsoe.eu/` | **HTTP 200** |
| Keycloak realm `https://keycloak.tp.entsoe.eu/realms/tp/.well-known/openid-configuration` | **HTTP 200** |
| 西班牙 EIC | **`10YES-REE------0`**（半岛 bidding zone） |
| 参数解析 | `documentType=A44`（日前价）+ `in_Domain`/`out_Domain`；`A75`（分技术实际发电）+ `processType=A16` + `in_Domain`；`A65`（实际负荷）+ `processType=A16` + `outBiddingZone_Domain` —— 四个探针均返回 401（**鉴权层**），未出现 400/参数错误 ⇒ 参数结构被接受 |

**关键判定**：401 的响应体是 **XML 协议应答**而非 HTML 拦截页 ⇒ 与 ESIOS 的处境（WAF 403、HTML 拦截页，见 [PF-013]）**本质不同**，ENTSO-E 链路在本机可通。

## 3. Token 申请流程（官方步骤）

1. 打开 `https://transparency.entsoe.eu/` → **Sign In** → **register**，注册并**通过邮件里的链接验证邮箱**。
2. 用**注册邮箱**发邮件至 **`transparency@entsoe.eu`**，**主题写 `RESTful API access`**，正文写注册用的邮箱地址。
3. 等待授权（官方说明**≤3 个工作日**），会收到确认邮件。
4. 登录平台 → **My Account** → 生成 **security token**。
5. 写入 `c:\work\meteo\.env`：`ENTSOE_API_TOKEN=<token>`（该文件已 gitignore）。

**两种鉴权方式**（官方说明）：`securityToken` **查询参数**，或 `Authorization: Bearer <token>` 头。本流程用前者（与 ESIOS 的 `Token token="…"` 头不同）。

> **另一条路（File Library）**：平台 2025 年后新增 File Library，走 **Keycloak** 取 token
> （`https://keycloak.tp.entsoe.eu/realms/tp/protocol/openid-connect/token`，URL-encoded body 参数），
> 适合批量/文件级下载。本流程暂用传统 REST（更简单，且已实测可达）。

## 4. 链路与产物

```
securityToken ──> web-api.tp.entsoe.eu/api
                     ├─ A44 日前价        ─┐
                     ├─ A75 分技术实际发电  ├─ IEC 62325 XML ──> 解析 ──> CSV
                     └─ A65 实际负荷       ─┘
```

- **请求**：按"月"分块（`periodStart/periodEnd = yyyymmddHHMM`，布鲁塞尔本地时间）。
- **解析**：命名空间无关的 `TimeSeries → Period → timeInterval/resolution/Point`；`position` 按 `resolution`（PT1M/PT5M/PT15M/PT30M/PT60M）换算为 UTC 时间戳；发电按 `MktPSRType/psrType` 分技术（B16 光伏、B19 陆上风电、B18 海上风电、B14 核电、B11/B12 水电、B10 抽蓄、B04 燃气、B05 硬煤…）。
- **缓存**：原始 XML 与解析后 CSV 均按月落盘，重复运行**自动跳过**已下载月份（符合平台"避免冗余请求"的要求）；ZIP 响应自动解包。

| 产物 | 说明 |
|---|---|
| `data/entsoe/price_da.csv` | `datetime_utc, price_eur_mwh` |
| `data/entsoe/gen_by_type.csv` | `datetime_utc, psr_type, gen_mw` |
| `data/entsoe/load.csv` | `datetime_utc, load_mw` |
| `data/entsoe/raw/*.xml|csv` | 按月原始缓存 |

## 5. 与项目既有结论的关系

- 本链路**不改变** PS-031/032/033 的机制结论（缺口=内生过剩标记、成因决定符号），而是为其提供**官方口径的独立复核**。
- 与 PS-035 衔接：PS-035 用的"实际光伏/负荷"来自 Energy-Charts；拿到 ENTSO-E 后可用 TSO 口径重算 `gap_w` 与 `S` 指数中的负荷项，检验 45 天负价概率是否稳健。
- **注意**：ENTSO-E 的"实际发电"是 TSO 报送的**并网口径**，与 Energy-Charts（同样源自 TSO/ENTSO-E 体系）高度相关但可能有时点/粒度差；**不保证**能给出 ESIOS 的"技术受限/弃电（restricciones técnicas）"指标 —— 该项仍为 ESIOS 独有。

## 6. 局限与未决

1. **token 未取得**：本流程为 draft，端到端数据拉取**尚未跑通**（401 为预期行为）。
2. **粒度取决于 TSO 报送**：ENTSO-E 不统一保证 5 min；西班牙的实际分辨率须拿到数据后核实。
3. **数据延迟**：实际发电/负荷按 TSO 报送节奏，通常有小时~天的延迟，不适合实时预警（实时预警仍受限）。
4. **无弃电/受限指标**：ESIOS 的 `restricciones técnicas` 在此不可得。
5. `psr_type` 映射表按 IEC 62325 标准整理，个别代码（如 B15/B17/B20）含义以返回数据核实为准。
