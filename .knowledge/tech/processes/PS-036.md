# [PS-036] 西班牙 ENTSO-E Transparency 数据链路（替代 ESIOS）

> 最后更新: 2026-09-29
> 成熟度: **verified**（token 已取得，A44/A75/A65 端到端跑通）
> 功能: ESIOS 因 REE 域名级 WAF 封锁（[PF-013]）不可达后，改用 **ENTSO-E Transparency Platform** 获取西班牙的**分技术实际发电 / 实际负荷 / 日前电价**，用于校核与细化 PS-029~PS-035 的西班牙链路
> 结论一句话: ENTSO-E 的 REST API 在本机**端点可达、协议正常**，token 到手后 **A44/A75/A65 全部 HTTP 200**，2023-01~2026-09（45 个月）已下载完成（价格 59,039 行 / 发电 2,654,432 行 / 负荷 131,126 行）；**价格与一手 OMIE 交叉校验三项完全一致**（2024-04-29 日均 58.27 / 最低 35.00 / 最高 102.26）；解析必须处理 **两处隐藏结构**——`curveType=A03` 变长块压缩 与 **A01/A07 合约混装**（否则静默污染数据，见 [PF-014]）

## 1. 背景与动机

西班牙链路（PS-029~PS-035）此前用 **Energy-Charts（Fraunhofer ISE）** 代理"实际分技术出力"，用 **OMIE** 拿日前价。二者都免注册、够用，但 ENTSO-E 是**欧洲输电运营商官方标准化口径**，可做三件事：

1. **口径校核**：把 Energy-Charts 的实际发电/负荷与 TSO 报送值对照，确认之前的结论不是数据源伪影。
2. **更细的时间分辨率**：ENTSO-E 按 TSO 报送粒度发布（解析器已支持 1/5/15/30/60 min），可用于日内结构分析。
3. **电价与出力同源对齐**：A44/A75/A65 均为同一平台、同一时区约定，避免跨源拼接的对齐风险。

## 2. 实测验证（2026-09-29）

| 项目 | 结果 |
|---|---|
| 端点 `https://web-api.tp.entsoe.eu/api` | 无 token 时 **HTTP 401 + `text/xml`** 的标准 `Acknowledgement_MarketDocument`（`Authentication failed.`），**不是** WAF 拦截页；**配置 token 后 A44/A75/A65 全部 HTTP 200** |
| 门户 `https://transparency.entsoe.eu/` | **HTTP 200** |
| Keycloak realm `https://keycloak.tp.entsoe.eu/realms/tp/.well-known/openid-configuration` | **HTTP 200** |
| 西班牙 EIC | **`10YES-REE------0`**（半岛 bidding zone） |
| 参数解析 | `documentType=A44`（日前价）+ `in_Domain`/`out_Domain`；`A75`（分技术实际发电）+ `processType=A16` + `in_Domain`；`A65`（实际负荷）+ `processType=A16` + `outBiddingZone_Domain` |
| 实测分辨率 | A44 = **PT60M**；A75/A65 = **PT15M**（2024-04 实测） |
| 完整性核对 | A44 2024-04 展开后 **744 行 = 期望 744**；A75 2024-04 **2880 个唯一时刻 = 30×96**（完整） |

**关键判定**：401 的响应体是 **XML 协议应答**而非 HTML 拦截页 ⇒ 与 ESIOS 的处境（WAF 403、HTML 拦截页，见 [PF-013]）**本质不同**，ENTSO-E 链路在本机可通。

> 🔴 **解析陷阱（必读，见 [PF-014]）**：ENTSO-E 报文中藏了两处会**静默污染**数据的结构。
> **① `curveType=A03`（变长块）**：连续相同的值只写一个 `Point`，其值**延续到下一个 Point 之前**。
> 按显式 `Point` 直接落库，A44 2024-04 只有 **573 行（应为 744）**，且被折叠掉的恰是**零价/负价**时段
> ⇒ 会系统性压低负价概率。必须按 `position` 前向填充展开到整段。
> **② `contract_MarketAgreement.type` 混装**：A44 同时返回 **A01（日前）与 A07（日内）**两套价格，
> 对同一时刻给出**不同值**（**A07 自 2025-09 起才出现**，所以 2025-08 之前的"干净解析"具有欺骗性）。
> 必须按合约过滤，日前价取 **A01**。

## 3. Token 申请流程（官方步骤）

1. 打开 `https://transparency.entsoe.eu/` → **Sign In** → **register**，注册并**通过邮件里的链接验证邮箱**。
2. 用**注册邮箱**发邮件至 **`transparency@entsoe.eu`**，**主题写 `RESTful API access`**，正文写注册用的邮箱地址。
3. 等待授权（官方说明**≤3 个工作日**），会收到确认邮件。
4. 登录平台 → **My Account** → 生成 **security token**。
5. 写入 `c:\work\meteo\.env`：`ENTSOE_API_TOKEN=<token>`（该文件已 gitignore）。

**两种鉴权方式**（官方说明）：`securityToken` **查询参数**，或 `Authorization: Bearer <token>` 头。本流程用前者（与 ESIOS 的 `Token token="…"` 头不同）。

> **另一条路（File Library）**：平台 2025 年后新增 File Library，走 **Keycloak** 取 token
> （`https://keycloak.tp.entsoe.eu/realms/tp/protocol/openid-connect/token`，URL-encoded body 参数），
> 适合批量/文件级下载。本流程暂用传统 REST（更简单，且已实测可达）。

## 4. 链路与产物

```
securityToken ──> web-api.tp.entsoe.eu/api
                     ├─ A44 日前价        ─┐
                     ├─ A75 分技术实际发电  ├─ IEC 62325 XML ──> 解析 ──> CSV
                     └─ A65 实际负荷       ─┘
```

- **请求**：按"月"分块（`periodStart/periodEnd = yyyymmddHHMM`，布鲁塞尔本地时间）。
- **解析**：命名空间无关的 `TimeSeries → Period → timeInterval/resolution/Point`；`position` 按 `resolution`（PT1M/PT5M/PT15M/PT30M/PT60M）换算为 UTC 时间戳；发电按 `MktPSRType/psrType` 分技术（B16 光伏、B19 陆上风电、B18 海上风电、B14 核电、B11/B12 水电、B10 抽蓄、B04 燃气、B05 硬煤…）。
- **缓存**：原始 XML 与解析后 CSV 均按月落盘，重复运行**自动跳过**已下载月份（符合平台"避免冗余请求"的要求）；ZIP 响应自动解包。

| 产物 | 说明 | 规模（2023-01~2026-09） |
|---|---|---|
| `data/entsoe/price_da.csv` | `datetime_utc, price_eur_mwh`（已过滤为日前 A01） | **59,039 行**；2023-01~2025-09 为小时、2025-10 起为 15 分钟 |
| `data/entsoe/gen_by_type.csv` | `datetime_utc, psr_type, gen_mw` | 15 分钟，分技术 |
| `data/entsoe/load.csv` | `datetime_utc, load_mw` | 15 分钟 |
| `data/entsoe/raw/*.xml\|csv` | 按月原始缓存（重跑只重解析、不重复请求） | — |

**价格数据交叉校验（一手 OMIE 对照）**：2024-04-29 日均 **58.27** / 最低 **35.00** / 最高 **102.26**，

### 4.2 数据质量提示（下游使用前须处理）

1. **`load.csv` 有 13 行 ≤ 0**（全部落在 2026-03，占 0.01%）——ENTSO-E 以 0 表示缺测，**必须当缺失处理**，否则会污染比值类计算。
2. **`B25` 代码含义未确认**：仅自 **2025-10** 起出现（约 11 个月），量级极小（均值 1 MW、最大 52 MW、无负值）；
   标准 PSR 映射表中未在本流程确认其定义 ⇒ 已标记为未知，**不影响主要结论**，但引用前应核实。
3. **粒度分层**：价格 2023-01~2025-09 为小时、2025-10 起为 15 分钟；发电/负荷全程 15 分钟。
   **跨 2025-09/10 做小时聚合时必须先对齐**（否则前后口径不一致）。
4. `gen_by_type` 中若干技术整期为 0（B02/B03/B07/B08/B09/B13/B18）⇒ 西班牙无该类装机，非缺数据。

## 5. 与项目既有结论的关系

- 本链路**不改变** PS-031/032/033 的机制结论（缺口=内生过剩标记、成因决定符号），而是为其提供**官方口径的独立复核**。
- 与 PS-035 衔接：PS-035 用的"实际光伏/负荷"来自 Energy-Charts；拿到 ENTSO-E 后可用 TSO 口径重算 `gap_w` 与 `S` 指数中的负荷项，检验 45 天负价概率是否稳健。
- **注意**：ENTSO-E 的"实际发电"是 TSO 报送的**并网口径**，与 Energy-Charts（同样源自 TSO/ENTSO-E 体系）高度相关但可能有时点/粒度差；**不保证**能给出 ESIOS 的"技术受限/弃电（restricciones técnicas）"指标 —— 该项仍为 ESIOS 独有。

## 6. 局限与未决

1. **粒度**：实测 A44 = `PT60M`、A75/A65 = `PT15M`（西班牙 TSO 报送）；ENTSO-E 不统一保证 5 min。
2. **数据延迟**：实际发电/负荷按 TSO 报送节奏，通常有小时~天的延迟，不适合实时预警。
3. **无弃电/受限指标**：ESIOS 的 `restricciones técnicas` 在此不可得 —— 这是本替代方案最大的功能缺口。
4. **A03 压缩必须展开**（[PF-014]）；展开后仍应对每个窗口做"实际槽位 / 期望槽位"核对。
5. `psr_type` 映射表按 IEC 62325 标准整理，个别代码（如 **B15/B17/B20/B25**）含义以返回数据核实为准（B25 未能确认）。
6. 价格已与**一手 OMIE** 交叉校验通过；**尚未与 Energy-Charts 的实际发电/负荷做数值比对**（下一步）。
7. **`load` 的 0 值（13 行）须当缺失**；`B25` 含义待确认。
