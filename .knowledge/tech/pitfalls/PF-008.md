# [PF-008] 怀俄明大学探空接口迁移与 SSL 证书问题

> **类型**: pitfall
> **成熟度**: verified
> **创建时间**: 2026-08-11
> **最后引用**: 2026-08-11
> **标签**: sounding, wyoming, ssl, certificate, china-network, server-migration, cgi-deprecated
> **适用阶段**: implement, verify

## 背景

2026年怀俄明大学进行了服务器迁移，旧 CGI 接口 `/cgi-bin/sounding` 已废弃（返回 404），改为新 WSGI 接口。同时，中国网络环境访问 HTTPS 站点时，代理服务器会拦截并替换 SSL 证书，导致 Python 默认的 SSL 验证失败。

## 陷阱 1: 旧 CGI 接口废弃

### 表现
- 访问 `http://weather.uwyo.edu/cgi-bin/sounding` 返回 404 Not Found
- 旧参数格式 `?region=naconf&TYPE=TEXT%3ALIST&YEAR=2026&MONTH=08&FROM=0100&TO=0112&STNM=72249` 不再可用

### 新接口 URL 格式
```
http://weather.uwyo.edu/wsgi/sounding?datetime=YYYY-MM-DD+HH:00:00&id=站号&src=UNKNOWN&type=TEXT:LIST
```

### 参数变化
| 参数 | 旧接口 | 新接口 |
|------|--------|--------|
| 日期 | YEAR/MONTH/FROM/TO 分离 | `datetime` 统一参数 |
| 站号 | STNM | `id` |
| 来源 | 区域码 | `src=UNKNOWN` |
| 格式 | TYPE | `type`（支持 TEXT:LIST / TEXT:CSV / PNG:SKEWT） |

### 解决方案
定期验证数据源 URL 可用性，使用新接口格式。

## 陷阱 2: SSL 证书验证失败

### 表现
```
urllib.error.URLError: <urlopen error [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain>
```

### 原因
中国网络出口处的代理/防火墙拦截 HTTPS 流量并替换了服务器证书，导致 Python 的 SSL 握手验证失败。这不是怀俄明大学服务器的问题，而是网络层面的问题。

### 解决方案
创建自定义 SSL 上下文，跳过证书验证：

```python
import ssl
SSL_CTX = ssl.create_default_context()
SSL_CTX.check_hostname = False
SSL_CTX.verify_mode = ssl.CERT_NONE

# 使用
resp = urllib.request.urlopen(req, timeout=60, context=SSL_CTX)
```

> **安全注意**：这仅适用于公开数据源（探空数据无需认证），不适用于需要身份验证的 API。

## 陷阱 3: ConnectionResetError

### 表现
```
ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接。
```

### 原因
中国网络不稳定，特别是在并行下载时，服务器可能主动断开连接。

### 解决方案
增加重试机制，最大重试 2-3 次：

```python
for attempt in range(max_retries):
    try:
        resp = urllib.request.urlopen(req, timeout=60, context=SSL_CTX)
        # 处理数据
        break
    except (socket.timeout, urllib.error.URLError, ConnectionResetError) as e:
        if attempt < max_retries - 1:
            time.sleep(3)
        else:
            return {"success": False, "error": str(e)}
```

## 预防措施

1. 定期（每月）使用 `--dry-run` 测试 URL 可用性
2. 将 SSL 跳过逻辑封装在下载函数中，避免全局修改 SSL 行为
3. 设置合理的超时时间（60秒）和重试次数（3次）
4. 记录 `_download_summary.json` 以便追踪下载失败情况
