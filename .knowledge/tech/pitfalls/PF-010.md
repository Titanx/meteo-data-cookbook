## 背景

怀俄明大学新 WSGI 接口将热力指数以 HTML 折叠表格展示，与旧 CGI 接口的纯文本格式不同。CAPE 在新格式中经常缺失，而 DCAPE 可以可靠提取。同时，从 HTML 中提取数值需要特殊的解析策略。

## 陷阱 1: CAPE 在新 WSGI 格式中缺失

### 表现
- 许多站点的探空数据中 CAPE 字段为空或不存在
- DCAPE 在所有站点中都可以提取到

### 原因
新 WSGI 接口的热力指数计算逻辑可能与旧接口不同，CAPE 的计算需要特定的温湿廓线条件，当条件不满足时留空。DCAPE 的计算则更稳健。

### 解决方案
- 使用 DCAPE 代替 CAPE 作为对流潜势指标
- 如需 CAPE，可考虑从 ERA5 再分析数据中提取
- 在分析报告中说明 CAPE 缺失情况

## 陷阱 2: HTML 表格解析复杂度

### 表现
新接口返回的 HTML 中，热力指数位于可折叠的 `<table>` 中，格式为：
```html
<tr><td>CODE</td><td>Full Name</td><td>value</td><td>unit</td></tr>
```
直接解析 HTML 表格需要处理复杂的嵌套结构。

### 解决方案
采用两步法：
1. 用 `re.sub(r'<[^>]+>', '\n', html)` 去除所有 HTML 标签
2. 在纯文本中用正则表达式匹配指数名称和后继数值

```python
plain_text = re.sub(r'<[^>]+>', '\n', html)
plain_text = re.sub(r'\n\s*\n', '\n', plain_text)

# 匹配 "DCAPE" 或 "Downward CAPE" 后面的数值
dcape_match = re.search(r'(?:^|\n)\s*(?:DCAPE|Downward CAPE)\s*\n\s*(-?[\d.]+)', plain_text)
if dcape_match:
    dcape = float(dcape_match.group(1))
```

### 为什么不用 BeautifulSoup？
- 增加外部依赖
- 简单场景下正则表达式更快
- 新 WSGI 格式稳定，正则匹配可靠

## 陷阱 3: PRE 块与 HTML 表格的分离

### 表现
新接口的 HTML 包含两个主要部分：
1. `<PRE>` 块：包含表格格式的探空廓线数据（温度、湿度、风等）
2. HTML 表格：包含热力指数（CAPE、DCAPE 等）

`<PRE>` 块可以用 pandas 的 `read_csv(sep='\s+')` 解析，而热力指数需要单独从 HTML 表格中提取。

### 解决方案
```python
# 1. 提取 PRE 块中的廓线数据
pre_match = re.search(r'<PRE>(.*?)</PRE>', html, re.DOTALL)
pre_text = pre_match.group(1).strip()
df = pd.read_csv(io.StringIO(pre_text), sep='\s+', skiprows=1)

# 2. 从 HTML 中提取热力指数

```

## 陷阱 4: 站点信息提取

### 表现
新接口中站点名称、经纬度等元数据分布在 HTML 的不同位置，需要分别提取：

```python
# 站点名称
name_match = re.search(r'Observations for Station \S+ at .*?UTC .*?([A-Z][A-Z\s,.\-]+?)(?:<|$)', html)

# 经纬度
lat_match = re.search(r'Latitude:\s*(-?[\d.]+)', html)
lon_match = re.search(r'Longitude:\s*(-?[\d.]+)', html)
```

### 注意事项
- 站点名称格式：`Observations for Station XXXXX at 12 UTC 10 Aug 2026 FORT WORTH, TX., USA`
- 经纬度可能为负值（西经/南纬），需保留负号
