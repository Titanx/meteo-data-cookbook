# [PF-011] NEXRAD 官方 S3 桶匿名访问限制与替代方案

> **类型**: pitfall
> **成熟度**: verified
> **创建时间**: 2026-08-12
> **最后引用**: 2026-08-12
> **标签**: nexrad, radar, s3, aws, anonymous, access-denied, forbidden, unidata, gcp, alternative
> **适用阶段**: architect, implement

## 背景

NEXRAD Level 2 雷达数据是强对流天气分析的核心数据源。NOAA 将数据托管在 AWS S3 上，但不同桶的访问策略不同，匿名用户可能无法访问。

## 陷阱 1: noaa-nexrad-level2 桶匿名访问已关闭

**现象**：匿名 s3fs 访问 `noaa-nexrad-level2` 桶返回 `Access Denied`。

**验证**（2026-08-12）：
```python
import s3fs
fs = s3fs.S3FileSystem(anon=True, client_kwargs={"region_name": "us-east-1"})
items = fs.ls("noaa-nexrad-level2/")  # ❌ PermissionError: Access Denied
```

**HTTP 直接访问**也返回 403 Forbidden：
- `https://noaa-nexrad-level2.s3.amazonaws.com/` → 403
- `https://noaa-nexrad-level2.s3.amazonaws.com/KFWS/` → 403
- `https://noaa-nexrad-level2.s3.amazonaws.com/index.html` → 403

**影响**：德州 14 个 NEXRAD 雷达站全部无法通过此桶匿名访问。

## 陷阱 2: noaa-nexrad-level3 桶不存在

**现象**：NEXRAD Level 3 产品数据桶名不存在。

**验证**：
```python
fs = s3fs.S3FileSystem(anon=True)
fs.ls("noaa-nexrad-level3/")  # ❌ "The specified bucket does not exist"
```

**尝试的桶名均失败**：`noaa-nexrad-level3`、`nexrad-level3`、`noaa-nexrad-l3`。

## 陷阱 3: NCEI THREDDS 服务器 URL 变更

**现象**：NCEI 的 THREDDS 目录访问返回 404。

**验证**（2026-08-12）：
- `https://www.ncei.noaa.gov/thredds/catalog/nexrad-level2/catalog.xml` → 404
- `https://www.ncei.noaa.gov/thredds/catalog/nexrad-level3/catalog.xml` → 404

**可能原因**：NCEI 的 THREDDS 服务器 URL 结构已变更，或不再公开提供目录浏览。

## 陷阱 4: Azure Blob 超时（中国网络）

**现象**：Azure Blob 存储的 NEXRAD 数据在中国网络环境下无法访问。

**验证**：
- `https://noaanexrad.blob.core.windows.net/nexrad-l2/` → 超时
- `https://noaanexrad.blob.core.windows.net/nexrad-l2?restype=container&comp=list` → 超时

## 解决方案

### 方案一：unidata-nexrad-level2-chunks（推荐实时方案）

Unidata 社区维护的实时分块桶，**匿名可访问**，203 个站点全部可达。

```python
fs = s3fs.S3FileSystem(anon=True, client_kwargs={"region_name": "us-east-1"})
stations = fs.ls("unidata-nexrad-level2-chunks/")  # ✅ 可达
# 获取 KFWS 最新体扫
vols = sorted(fs.ls("unidata-nexrad-level2-chunks/KFWS/"), reverse=True)
chunks = sorted(fs.ls(vols[0]))
```

**限制**：仅保留最近~10个体扫，非标准 NEXRAD 文件格式，无历史归档。

### 方案二：GCP 公开数据集（推荐归档方案）

Google Cloud Storage 提供 NEXRAD L2/L3 数据，HTTP 目录可达。

```bash
# 列出目录（HTTP 浏览器）
# https://storage.googleapis.com/gcp-public-data-nexrad-l2/
# 使用 gsutil 下载
gsutil ls gs://gcp-public-data-nexrad-l2/KFWS/
```

**限制**：需要 gcloud SDK 或 gsutil，HTTP 直接访问无法获取具体文件。

### 方案三：RainViewer API（推荐可视化方案）

全球雷达拼图，免费无 key，5 分钟延迟。

```python
import requests
r = requests.get("https://api.rainviewer.com/public/weather-maps.json")
```

**限制**：仅 PNG 瓦片，非原始反射率数据。

### 方案四：NWS API（元数据方案）

获取雷达站元数据，208 个站点信息。

```python
import requests
r = requests.get("https://api.weather.gov/radar/stations")
```

**限制**：仅元数据，无实时雷达数据。

## 快速决策表

| 需求 | 推荐方案 | 访问方式 |
|------|---------|---------|
| 实时原始雷达数据 | unidata chunks | s3fs 匿名 |
| 实时可视化 | RainViewer API | HTTP GET |
| 历史归档 | GCP NEXRAD L2 | gsutil |
| 雷达站元数据 | NWS API | HTTP GET |
| 标准 NEXRAD 文件格式 | GCP NEXRAD L2 | gsutil/gcloud |

## 经验教训

1. **NOAA 官方 S3 桶已不再匿名可访问**：不要依赖 `noaa-nexrad-level2` 的匿名访问，改为使用 Unidata 或 GCP 方案。
2. **NEXRAD Level 3 无公开匿名桶**：需要 Level 3 产品（如反射率拼图、速度产品）时，使用 RainViewer 或 GCP 替代。
3. **中国网络环境下 Azure 不可达**：Azure Blob 的 NEXRAD 数据对国内用户不可用，优先使用 GCP 或 AWS 方案。
4. **多源验证**：对同一需求，始终测试 2-3 个替代方案，避免单一数据源依赖。
